# L19｜Dan Fu：推理约束如何反过来塑造架构

> Spring 2026。以用户提供的完整 guest-dan-fu.txt 为主线，按课堂讨论顺序展开。本讲无独立官方课件。未逐句回听音频。

本章只预设基本 Python、矩阵运算和概率/求导知识；第一次用到的课程术语在正文解释。嘉宾先从真实推理流量和服务错误出发，再进入 megakernel 的设备侧调度，之后讨论循环模型，最后用问答限定研究结论。

## 1. 从训练完成那一刻开始思考

一个推理服务接收请求、处理输入、逐 token 生成并返回结果。TTFT 是首个 token 前的等待，包含排队和输入处理；decode 是随输出逐步扩展的阶段。权重固定不代表运行条件固定，缓存命中、长度、工具交互和并发都会改变瓶颈。

训练决定模型会什么，推理系统决定这些能力以多大成本、什么延迟提供给用户。尤其是代码与 agent 工作负载，输入可能很长、请求之间共享前缀，输出还会触发下一轮工具交互，无法只用一个固定形状的矩阵乘法代表。

本讲围绕三层展开：真实流量中的推理问题，跨算子执行的 megakernel，以及重复使用参数的 looped Transformer。它们共同说明：系统约束会改变值得探索的模型结构。

## 2. 真实流量是一种分布

前缀缓存保存相同历史计算留下的状态，KV cache 具体保存每层的 Key、Value 向量；它不是用户文字的简单压缩文件。跨轮会话可重用共同前缀，新输入和分叉内容仍需独立处理。平均长度相同的流量也可能有不同长尾和排队，所以应看分布与延迟分位数。

请求有不同 prompt 长度、输出长度、到达时间和缓存命中情况。平均长度相同的两种流量，也可能因长尾比例不同而产生完全不同的排队和显存峰值。

代码 agent 可能每次携带很长仓库上下文，只需要生成短命令；另一些任务则 prompt 很短、输出很长。前者主要增加 prefill 压力，后者长时间占用 decode 槽位。服务策略需要针对实际分布，而不只是一个“典型请求”。

**补充理解：** 推理优化更像运营车站，而不是只测试列车最高时速：班次到达、换乘、长尾与拥堵共同决定体验。

### 请求、缓存与正确性

一个请求先分词和路由，查询前缀状态，再执行新增位置的 prefill/decode，采样后还需处理停止标记、工具调用等协议。实际负载还包含会话轮数、轮间间隔、回访概率和 SLA；一次性文档批处理与反复往返的 coding agent，不能只用相同平均 token 数代表。

缓存可形成 GPU→CPU DRAM→SSD/其他存储的层级，命中后仍有迁移和等待成本。逐出/预取要结合重用概率和 SLA，打开旧会话可作为预取信号。LRU 是课堂举的直觉，不能把口述“约两倍最优”当成无条件算法保证。

Cache-aware prefill/decode disaggregation 按命中情况分组冷/温请求，避免长新输入拖延短增量处理。课堂最高约 40% 收益来自特定配置，不保证所有流量。更大互联域还带来上下文切分和单卡故障恢复的问题。

嘉宾列出 NaN 引起重复 token、工具协议错误引起重试长循环、越界读取未初始化值诱发异常语言等案例。症状与原因不是一一对应，不能把奇怪输出都归因于模型训练，也不能只凭换语言就断定越界。海量请求会放大极低概率错误，需要边界形状与长时间运行核验。

## 3. Prefill/decode 分离的收益与成本

prefill 可同时处理已知输入，decode 每步依赖上一生成结果。分离部署是让两种工作分别使用更合适的资源池；移交的状态可能很大，还要考虑传输、格式和故障恢复。只比较两台设备各自速度不足以决定整个请求是否更快。

Prefill 更接近大矩阵计算，decode 常受权重与 KV 读取限制，因此可把两者放在不同设备池，分别调度。完成 prefill 后，把所需状态交给 decode 设备。

分离并非免费：必须传输 KV、考虑网络和布局兼容、管理队列和故障恢复。如果传输成本超过调度收益，结果可能更差。长 prompt、前缀复用、设备异构与链路带宽会改变最优选择。

服务正确性也会受到低层实现影响。一个位置偏移、cache 索引或 mask 的错误，可能表现为模型“莫名其妙换语言”或生成异常。不能把所有奇怪行为都解释成模型能力或训练分布问题。

## 4. 独立 kernel 的边界可能造成浪费

kernel 是一次设备执行程序，megakernel 试图在更大计算范围内管理多段工作。任务依赖图中，边表示必须等待的数据关系；没有边的加载可能提前，但真正消费数据仍必须等就绪。设备侧调度把部分排队与同步控制移到 GPU，并不允许绕过数学依赖。

传统执行常把 QKV、位置处理、Attention、输出投影等作为多个 kernel。每个 kernel 内部可以优化得很好，整体仍会有启动间隙、尾部等待和无法提前搬运的数据。

Megakernel 把更大一段计算放进一个执行框架，在设备侧调度有依赖的任务。课堂举例：在 QKV 与 RoPE 完成前，提前读取 Attention 需要的旧 KV；在 Attention 计算期间，提前加载输出投影权重。

这里并不是“依赖可以忽略”，而是把加载与计算拆开：某些数据准备不依赖上一步的最终结果，能够提前进行。真正消费数据的计算仍需等待对应依赖满足。

### Megakernel 的收益与工程代价

独立 kernel 的启动/结束、尾部等待与全局依赖边界会累积空闲。Megakernel 把 GPU 看成需要调度的任务图：提前加载旧 K/V、输出投影权重，安排可提前的归约，同时遵守真正的数据依赖。ThunderKittens 提供较细的控制；它不是忽略依赖的魔法。

课堂展示的约 72% 带宽利用率和若干加速幅度只适用于对应模型、设备与形状，“speed of light”不是绝对最优证明。专门写少数模型、有限 batch 范围的整体 kernel 已很费工，batch 或硬件变化可能要求重新设计。多 GPU 通信也可纳入部分融合，但 collective 延迟依然存在；实际可只融合 attention 或 MoE 的某段，而非强制整个模型一个 kernel。

## 5. 设备侧调度为什么困难

寄存器、共享内存和硬件并发是有限资源。把程序融合得更大可能省启动和中间读写，也可能提高资源压力、降低形状覆盖并增加维护成本。评价要同时看关键路径、数据移动与可适用的模型范围。

需要管理工作队列、数据就绪、共享存储、同步与资源占用。融合范围更大，可能减少启动与 HBM 往返，也可能提高寄存器压力，降低通用性，并让调试更困难。

把 GPU 看成许多 worker 组成的系统，有助于理解任务图调度；但 GPU 的同步、内存一致性和资源限制与普通服务器不同，不能直接照搬线程池。更多融合也不自动更快，必须比较整体关键路径。

作者团队的 [ThunderMLA 说明](https://hazyresearch.stanford.edu/blog/2025-03-04-thundermla)可作机制补充。这里不把嘉宾在某配置上展示的速度或带宽数字推广为所有模型的保证。

## 6. 参数复用：用循环增加计算深度

普通深层网络给各层独立参数，循环模型多次调用共享的变换 F_θ。共享参数减少权重容量，但不同循环深度的隐藏表示和状态未必相同；“同一权重”不等于“同一 KV”。增加循环次数还会增加串行工作和训练激活。

普通固定深度模型每层使用自己的参数；looped 模型让表示多次经过共享 block。提高循环次数可以增加 FLOPs，而不按相同比例增加参数存储。

教学形式为 (h_{t+1}=F_\theta(h_t,e))，其中 e 是初始输入表示。循环增加有效深度，但也增加顺序计算、训练激活和可能的缓存开销。参数更少不意味着延迟一定更低，更不意味着推理内存只有一份权重。

文字稿将项目名转写成多个拼法；已按作者的[Parcae 项目页](https://sandyresearch.github.io/parcae/)与[论文](https://arxiv.org/abs/2604.12946)校正为 **Parcae**。相关项目资料只用于确认名称与稳定化机制。

### Parcae：实验、简化与未知

研究从循环模型对学习率敏感、出现 spike 出发，再分析残差中的递推与输入注入。把复杂非线性放进 r、先观察 A/B 主导行为，是分析简化，不是证明非线性无关紧要。仅用 norm 压住激活幅度也未必消除优化冲突。项目名称按作者资料校正为 Parcae；谱半径/谱范数、连续/离散稳定性的区别见正文，不能照抄字幕的概念混用。

固定参数和 FLOPs 时，增加循环需要在数据量等处交换预算；展示的配对实验支持该范围内探索循环，而非“免费增加计算”。联合扩展数据/参数/循环的趋势仍是经验结果，不支持无限外推。直接在已训练模型中循环少数层的现象，在问答中只是初步观察，尚无完整解释。

较少参数可能跨过“更少设备即可装下”的阈值，减少通信、腾出 KV 空间，但每 token 仍要多次执行共享块。把整个循环块放入快速片上存储并以小 megakernel 运行，是讲者尚未实现的研究设想，不能写成已有成果。

Co-design 的最后问答还比较批处理表示提取与自回归会话：前者可能采用双向编码器，后者重视 decode 和热缓存；硬件容量、量化格式、KV 与工作流共同限制架构。课堂的厂商交易、前沿模型内部结构猜测和硬件预测未作为已核实事实转载。

## 7. 稳定性：谱半径不是“另一种范数”

矩阵特征值描述某些方向反复作用的伸缩，谱半径是特征值模的最大值；奇异值描述单次作用的长度伸缩，谱范数是最大奇异值。非正规矩阵可在长期衰减的同时先产生很大瞬时放大，单次范数与长期幂行为不能混为一谈。

课堂用简化动力系统解释重复应用变换的风险。作者补充的线性教学模型为：

$$
h_{t+1}=Ah_t+Be,\qquad h_t=A^t h_0+\sum_{j=0}^{t-1}A^jBe.
$$

若标量 A=2，重复 16 次会出现 2¹⁶ 的放大。矩阵情形要分析幂 Aᵗ：谱半径是最大特征值模，谱范数则是最大奇异值，二者一般不相等。对非正规矩阵，即使谱半径小于 1，有限步也可能出现瞬时放大。

离散线性系统中谱半径小于 1 约束长期稳定；更强的范数约束可以帮助控制瞬时增长。完整非线性循环模型还需分析相应假设，不能从这个线性算例直接得出全局保证。

另一个需要校正的口述简写是“负对角矩阵就稳定”。连续时间中负实部与稳定有关；离散更新需要对应特征值模小于 1。Parcae 使用与离散化相关的受约束参数化，不能直接把任意负数放进离散更新，例如 −2 仍会放大。

## 8. 给 scaling 多加一个维度

在参数 N、数据 D 之外加入循环次数 R 后，固定预算时这些变量需要交换资源。比较必须说明 FLOPs、存储、延迟与质量的约束；只有“参数更少”不能证明部署整体更便宜。

在参数 N、数据 D 之外，再加入循环次数 R。研究问题是：给定参数或 FLOPs 预算，增加数据和循环各带来多少收益？应比较匹配预算的实验，而不是把更多循环的结果直接与更少计算的基线比较。

嘉宾展示的趋势提供了继续探索的证据，不是证明所有模型都应该无限循环。收益可能饱和，训练与测试时改变循环数也可能产生不同分布。还需要测延迟、缓存与真实任务，而不只看参数量和验证 PPL。

## 9. 如何把本讲转成研究练习

先选一个清楚的约束：显存、首 token 延迟、单请求 decode 速度或单位费用。固定工作负载与质量目标，然后问瓶颈在哪一层：数据流、调度、算子还是架构。

- 如果瓶颈是算子间空闲，可测预取和更细粒度调度。
- 如果瓶颈是权重容量，可研究参数共享，但同时计入循环计算和状态。
- 如果瓶颈是长上下文缓存，可回看 GQA、MLA 与上下文管理，而不是直接增加 GPU。

## 深入算例与补充理解

### 用任务依赖图理解跨算子重叠

假设步骤 A 生成 Query，步骤 B 加载旧 K/V，步骤 C 计算 Attention，步骤 D 加载 O 投影权重，步骤 E 做 O 投影。C 依赖 A 和 B，E 依赖 C 和 D；但 B 不一定依赖 A，D 也不一定依赖 C。

传统逐 kernel 边界可能安排 A→B→C→D→E。更细粒度调度则可让 A 与 B 重叠、C 与 D 重叠。收益来自识别真正依赖，而不是把所有操作都强行并行。还要保证重叠没有争抢相同带宽导致净损失。

### 为什么不是所有工作都适合 megakernel

动态分支、不同 batch 形状、复杂多卡通信与大量共享状态，会增加设备侧调度复杂度。一个专为 batch=1 调优的整体 kernel，不一定适合高吞吐服务。高性能原语与通用调度之间存在工程折中。

评估时可以分别比较单请求延迟、形状覆盖、维护成本、编译成本和峰值显存；若只选择最有利的一个形状，容易高估通用收益。

### 参数共享与 KV cache 的一个反直觉问题

重复使用同一层权重，不代表每一轮循环都能共用相同 K/V。不同循环深度的隐藏表示可能不同，对应 Key/Value 也不同。若实现为每个循环深度保存独立状态，cache 仍可能随循环次数增长。

因此研究 looped 模型的部署成本时，至少要把权重、每层/每轮状态、执行次数和数据依赖分别列出来。节省参数是明确收益之一，却不是全部内存和延迟账本。

### 线性稳定性算例的边界

A=0.9 时，无输入的标量系统会衰减；有固定输入 b 时，状态趋于 b/(1−0.9)，可能比 b 大十倍。可见“稳定”也不意味着“激活总是很小”，注入尺度同样重要。

对完整非线性模型，局部 Jacobian 随状态与输入变化，单个固定 A 的分析只能提供设计直觉和部分约束。可靠结论还需要训练曲线、不同学习率、循环次数和数据范围的实验。把简化推导的适用边界说清楚，比把它包装成万能证明更有助于学习。

## 独立完成一个小算例

A=[[0.5,10],[0,0.5]] 的两个特征值都为 0.5，谱半径小于 1。对初始向量 [0,1]，一次作用得到 [10,0.5]，长度显著放大；之后长期仍会衰减。这说明“谱半径小于 1”与“任何有限步都不放大”不是一回事，训练还需检查实际激活与梯度。

## 10. 自测

1. 为什么 prefill/decode 分离可能让网络成为新瓶颈？
2. 提前读取 K/V 与提前计算完整 Attention，有什么依赖差别？
3. 权重共享的循环模型为何仍需要更多推理计算？
4. A=−2 的离散系统稳定吗？为什么不能只看“负号”？

**参考思路：** 第四问的绝对值为 2，会指数放大；系统与架构结论都要回到明确的数学模型和预算条件。

### 逐题推理

1. 分离阶段后必须传输 KV、重新排队并适配布局；通信可能成为新的关键路径。
2. 读取旧状态可先于新 Query 就绪，真正 attention 结果则依赖两者；预取数据不等于提前完成依赖计算。
3. 每轮调用虽共享参数，却仍要执行计算并可能保存不同状态，权重节约不能当作零延迟。
4. A=−2 的离散递推幅度每轮翻倍；连续时间的负特征值条件不能直接搬到离散更新。
