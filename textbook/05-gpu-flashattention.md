# L05｜GPU 怎样工作，FlashAttention 为什么更快

> Spring 2026 · 中文教材（含 Transcript 对照补遗）。主要依据用户提供的 `lecture-05.txt`，并结合[官方 PDF](https://github.com/stanford-cs336/lectures/blob/de53a9f979a6ee35f7d13a5e1aadee5ea1afc58e/lecture_05.pdf)。 时间定位：00:05–约 30:00 硬件；约 30:02–68:00 性能；约 70:01–78:31 FlashAttention。 课件重点页：8–18、22–48、50–54（PDF 页码从 1 开始）。正文按知识逻辑重组，不是逐字翻译；“补充理解”与教学算例为作者解释。未逐句对照录音。

## 1. GPU 快在哪里

CPU 更关注少量复杂线程的延迟，GPU 更关注大量相似工作的总吞吐。GPU 用许多执行单元处理并行数据，再用大量驻留任务隐藏访存等待。Tensor Core 等专用矩阵单元进一步提高了特定精度和形状的矩阵乘法吞吐。

因此“GPU 很快”有前提：工作要能并行，数据要及时送到计算单元，形状和精度要适合硬件。短小、分支多、依赖长的代码不一定受益。

## 2. 线程层级与内存层级

线程组成 block，block 被调度到 SM；在常见 NVIDIA 执行模型中，warp 通常由 32 个线程组成。block 内线程能协作并共享片上存储；跨 block 的协作一般需要其他同步或分阶段 kernel。

| 层级 | 用途 | 主要限制 |
| --- | --- | --- |
| 寄存器 | 线程的局部值与累加器 | 容量有限，过量可能溢出到较慢存储 |
| 共享内存／片上缓存 | block 内复用与交换 | 容量、布局、bank conflict |
| L2 | 跨 SM 的缓存复用 | 命中率与容量依赖工作集 |
| HBM／全局内存 | 保存大模型与输入输出 | 带宽和访问延迟 |

具体数量随型号变化。文字稿中口述规格与后续例子可能不一致，本教材用机制解释，不把某个 SM 数写成所有 GPU 的固定属性。TPU 的执行组织不同，但同样需要高效矩阵运算与数据复用。

## 3. 六种优化，其实在解决不同问题

- **减少分支发散：** 同一 warp 的线程走不同分支时，可能需要分阶段执行路径。
- **低精度：** 减少字节数，并利用更快的矩阵指令；需要控制数值误差。
- **融合：** 中间结果留在片上，减少 HBM 往返和启动开销。
- **重计算：** 有时重新算一个值，比保存和重读更划算。
- **合并访存：** 相邻线程尽量访问合适的连续地址，减少无效内存事务。
- **分块：** 一次加载的数据服务多次计算，提高复用。

不要把它们简单理解成“减少 FLOPs”。重计算可能增加 FLOPs，却减少真正的瓶颈。

## 4. 用分块矩阵乘法理解复用

计算 `C=A@B` 时，朴素方法为每个 C 元素反复读取 A 的一行、B 的一列。相邻输出明明需要很多相同输入，却重复从 HBM 获取。

分块方法让一个 block 负责 C 的一个 tile，沿归约维度依次加载 A/B 的对应子块，在片上累积。若块边长为 b，每份输入可以服务约 b 次乘加，算术强度随 b 提升。

但 b 不能无限增大：共享内存和寄存器装不下，驻留 block 变少，尾块也可能浪费更多计算。选择 tile 是多约束优化，而不是越大越好。

**教学算例：** 一个 GPU 若每轮理想调度 100 个同样大小的 block，100 个 block 一轮完成，101 个就可能需要第二轮。这是 wave quantization 的直觉。真实 SM 可同时驻留多个 block，实际波次必须结合资源占用判断。

## 5. Attention 的大中间矩阵

标准 Attention 先计算 `S=QKᵀ/√d_h`，再做 `P=softmax(S)`，最后 `O=PV`。S 和 P 的形状随 T² 增长。即使最终 O 只有 T×d_h，也可能把巨大的中间矩阵多次写回和读出。

FlashAttention 的目标是计算同一个稠密 Attention，在允许的浮点舍入差异下，避免显式保存完整的 S/P 到 HBM。它不是稀疏 Attention，也没有把所有算术量从平方变成线性。

## 6. 在线 softmax：为什么可以分块算

对已经处理的 logits，保存最大值 m 和归一化和 ​l=Σexp(s−m)。新块出现后，最大值变成 m'。旧指数和必须改用新的基准，因此：

$$
m'=\max(m,\max_j s_j),
$$
$$
l'=e^{m-m'}l+\sum_j e^{s_j-m'}.
$$

再保存未归一化的输出向量 a：

$$
a'=e^{m-m'}a+\sum_j e^{s_j-m'}v_j.
$$

全部块处理完，输出 (o=a/l)。关键不是局部 softmax 各算各的再平均，而是**持续统一指数的缩放基准**。

教学算例：第一块只有 logit 0，保存 m=0、l=1。第二块只有 logit ln2，新 m'=ln2，旧和变为 1/2，新项为 1，所以 l'=1.5。两个位置的最终权重是 1/3 与 2/3，和一次性 softmax 相同。

初始化时 m=−∞、l=0，实际实现要正确处理全遮罩行和第一次更新，避免出现 `−∞−(−∞)` 造成 NaN。

## 7. FlashAttention 把这些机制组合起来

固定一个 Query tile，依次读入 K/V tile，计算局部 scores，应用因果 mask，用在线规则更新最大值、分母和输出累加器，最后写回结果。反向可以重新计算部分中间值，减少前向保存量。

**补充理解：** 我们并没有“忘掉”完整注意力矩阵里必须的信息，而是识别出最终输出只需要特定的归约统计量。找到这种充分的中间状态，往往比单纯减少乘加更有价值。

不同版本和硬件的具体流水、并行切分、累加精度会不同。因此性能结论要附序列长度、head dimension、dtype 和设备，不能写一个脱离环境的固定加速倍数。

## 深入算例与补充理解

### 从两块推广到任意块：在线统计为什么可靠

旧块的 a 和 l 都以 exp(−m) 为基准，新块要用 exp(−m')。把旧值同时乘 exp(m−m')，就把旧项和新项放回同一坐标系。只缩放分母、不缩放输出分子，会得到错误的结果。

这类算法的一个好处是可以把两组已计算的统计量合并，而不一定逐 token 更新。若左右两块最大值为 m1、m2，令 m=max(m1,m2)，分别缩放各自分母与分子后相加即可。因此分块顺序能够灵活安排；浮点顺序仍会引入小误差。

### T² 中间结果到底有多大

令 B=2、h=32、T=8192，单个 `[B,h,T,T]` BF16 张量容量为 8 GiB。若同时保存 scores、probabilities、dropout mask 等，远不止这一份。对比最终 `[B,T,d]`，若 d=4096，其 BF16 容量是 128 MiB。

这说明 Attention 瓶颈不仅来自乘法多，更来自中间表示远大于输入输出。FlashAttention 的巨大价值就在于改变了中间状态保存方式。这里仍不能把缓存全部历史 K/V 的成本忽略掉，那是另一项线性随长度增长的状态。

### 合并访存不等于“地址越连续越好”这么简单

对行主序矩阵，同一行相邻列通常连续，不同行同一列则隔着 stride。线程映射决定一个 warp 最终发出哪些地址。若输入转置或做了 padding，逻辑相邻与物理相邻未必相同。

还要考虑对齐、事务大小、cache 行与实际硬件访问方式。因此“我按行写代码”不是 coalescing 的充分证据；需要画出各 lane 的字节地址，再结合 profiler 看内存事务效率。

### 一个好的 GPU 直觉应带边界

融合往往减少往返，却可能让寄存器不够；低精度减少数据量，却可能引入解量化；加大 tile 提高复用，却可能减少驻留工作；重计算省激活，却可能使本来计算受限的部分更慢。

这些都可以在 roofline 与资源约束下解释。优化的正确姿势不是收集一串“总会更快”的技巧，而是先判定当前瓶颈，再预言改动会怎样改变 F、Q、并行度与峰值存储，并用数据检验。

## 8. 自测与实验

1. 用上面的两个 logits 手算在线分母和加权输出。
2. 比较 T 翻倍后朴素 Attention 的 scores 容量与 KV cache 容量变化。
3. 为什么 padding 到更规整的形状，有时会让更多计算反而更快？
4. 设计一个测试，比较朴素 Attention 与分块版本，覆盖因果 mask、非整块长度和不同数值尺度。

**参考思路：** scores 随 T²，cache 在固定模型下随 T；对齐收益需要超过填充成本；比较要用误差容限，并检查不能访问未来位置。

CPU 强调复杂控制和单任务延迟，GPU 借大量可调度 warp 提高吞吐，线程等待访存时可切换到其他就绪 warp。Block 的 shared memory 由程序显式管理，L1/L2 cache 则由硬件缓存机制管理；线程私有的 local memory 名称也不意味着物理上一定是片上快存，寄存器溢出可能落到设备内存。SIMT 的锁步讨论应以 warp 为基本范围，不能说全 GPU 的所有线程必须同时执行同一句指令。

课堂也比较 TPU：两类设备都有慢速大容量存储、片上存储与专用矩阵单元，但单元数量/大小、控制灵活性和网络不同。“TensorCore”在不同设备资料中的命名层级还可能不同，不能直接把计数互比。Dennard scaling 放缓以后，进步更依赖并行、矩阵专用单元和低精度；矩阵算力增长快于带宽，是本讲反复强调数据移动的原因。

### 低精度、重计算与访存的具体限制（约 30:00–66:00）

Warp divergence 会使不同分支上的线程分批执行或受掩码控制，但不是看到 `if` 就一定慢；分支是否在 warp 内一致、编译器是否谓词化都重要。低精度矩阵乘法常用低精度输入、更高精度累加；分组尺度会让转置后的分组边界不同，某些方案因此维护原布局和转置布局的量化表示，增加转换与存储开销。

字幕在约 42 分钟把“四位可表示值 −6 到 6”的说明与 MXFP8 名称混在一起；这里保留**四位编码加块缩放**的机制，不把转写名称当作格式规范。缩放因子可以来自当前块统计或历史统计，不必是通过梯度训练的参数。输入/输出层等敏感位置也不应因为主体支持低精度就全部强制转换。

重计算的目的不仅是让模型装得下，也可减少中间激活的 HBM 读写，带宽受限时增加 FLOPs 仍可能更快。合并访存要结合每个 warp 的地址分布、物理布局、对齐和事务粒度；一次读取并不意味着“整行整列免费”。Tiling 的收益来自片上复用，tile 过大则可能占满寄存器/shared memory，降低并发。

### 为什么矩阵稍大反而吞吐骤降（约 60:00–72:00）

有两种不同的量化效应：**tile quantization** 是边缘 tile 大量位置被 mask，**wave quantization** 是 tile 数略超过一波可并发工作的容量，迫使少量尾部 tile 单独等下一波。课堂用 98 与 120 个 tile、108 个 SM 的简化例子说明后者。现实中每 SM 可驻留的 block 数取决于资源，不能把“一 SM 一 block”当成通则。Padding 有时增加算量却改善对齐和利用率，是否有利必须测量。

### FlashAttention 的精确性说到哪一层（约 72:00–结尾）

FlashAttention 将分块、融合、在线 softmax 和反向重计算组合起来。在线过程保留行最大值、指数和、加权 value 和；遇到更大最大值时，旧统计必须按新尺度重缩放，不能只改最大值。反向保存必要的紧凑统计，再按 tile 重算局部分数，避免存完整 T×T 概率矩阵。

它对标准 attention 是数学等价的重新组织，浮点归约顺序仍可能改变末位误差；节省 HBM 中间量不代表标准 dense attention 的 FLOPs 已变成线性。性能还受 tile 调度和硬件代际影响，不能把某张图上的加速倍数写成所有形状的承诺。
