# L05｜GPU 怎样工作，FlashAttention 为什么更快

本章只需要基本 Python、矩阵运算和概率/求导知识，新的术语会在使用时解释。我们先建立 GPU 的执行与存储模型，再逐个讨论优化手段，最后把分块和在线 softmax 组合成 FlashAttention。

## 1. GPU 快在哪里

把 GPU 想成许多执行工作者并行处理数组。吞吐是单位时间完成的工作量，延迟是一次工作等待多久；擅长吞吐不表示短小任务也一定低延迟。FLOP 是一次浮点操作，FLOP/s 是速度，矩阵专用单元的规格也只适用于相应类型与精度。

CPU 更关注少量复杂线程的延迟，GPU 更关注大量相似工作的总吞吐。GPU 用许多执行单元处理并行数据，再用大量驻留任务隐藏访存等待。Tensor Core 等专用矩阵单元进一步提高了特定精度和形状的矩阵乘法吞吐。

因此“GPU 很快”有前提：工作要能并行，数据要及时送到计算单元，形状和精度要适合硬件。短小、分支多、依赖长的代码不一定受益。

## 2. 线程层级与内存层级

SM 是 GPU 上调度和执行线程块的处理单元；thread 是线程，warp 是常见 NVIDIA 模型中协同执行的一组 32 线程，block 是能协作和共享部分存储的线程组。寄存器通常保存线程局部值，共享内存供块内复用，HBM 是容量较大的设备显存。程序中的逻辑数组和编译后实际放置位置需要区分。

线程组成 block，block 被调度到 SM；在常见 NVIDIA 执行模型中，warp 通常由 32 个线程组成。block 内线程能协作并共享片上存储；跨 block 的协作一般需要其他同步或分阶段 kernel。

| 层级 | 用途 | 主要限制 |
| --- | --- | --- |
| 寄存器 | 线程的局部值与累加器 | 容量有限，过量可能溢出到较慢存储 |
| 共享内存／片上缓存 | block 内复用与交换 | 容量、布局、bank conflict |
| L2 | 跨 SM 的缓存复用 | 命中率与容量依赖工作集 |
| HBM／全局内存 | 保存大模型与输入输出 | 带宽和访问延迟 |

具体数量随型号变化。进行资源核算时，应使用具体型号启用的 SM 数、容量与带宽。TPU 的执行组织不同，但同样需要高效矩阵运算与数据复用。

### 硬件执行与存储的具体限制

CPU 强调复杂控制和单任务延迟，GPU 借大量可调度 warp 提高吞吐，线程等待访存时可切换到其他就绪 warp。Block 的 shared memory 由程序显式管理，L1/L2 cache 则由硬件缓存机制管理；线程私有的 local memory 名称也不意味着物理上一定是片上快存，寄存器溢出可能落到设备内存。SIMT 的锁步讨论应以 warp 为基本范围，不能说全 GPU 的所有线程必须同时执行同一句指令。

再比较 GPU 与 TPU：两类设备都有慢速大容量存储、片上存储与专用矩阵单元，但单元数量/大小、控制灵活性和网络不同。“TensorCore”在不同设备资料中的命名层级还可能不同，不能直接把计数互比。Dennard scaling 放缓以后，进步更依赖并行、矩阵专用单元和低精度；矩阵算力增长快于带宽，是本章反复强调数据移动的原因。

### 硬件计数和内存术语

区分完整芯片设计与实际产品启用的单元。完整 GA100 设计具有 128 个 SM，而这里使用的 A100 算例启用 108 个 SM；二者可在 [NVIDIA Ampere 官方说明](https://developer.nvidia.com/blog/nvidia-ampere-architecture-in-depth/)中核对。计算并行度和尾波利用率时，必须始终使用目标设备的实际单元数。

CUDA 中的 local memory 是线程私有的逻辑地址空间，不能因 local 一词就归为片上快存；它可以位于设备内存。shared memory 的程序管理方式与硬件 cache 也不同。[CUDA 官方编程指南](https://docs.nvidia.com/cuda/archive/13.2.2/cuda-programming-guide/02-basics/writing-cuda-kernels.html)可用于确认这个术语。warp 内的分支才是本章 divergence 的关键范围；同一个 warp 都走同一分支时，不必把另一分支也执行一遍。每 block 的 warp 数取决于线程数（向上按 32 分组）及资源约束，不是每种 GPU 唯一固定的数。

### TPU 对照表的适用范围

H100 与 TPU v5p 都有矩阵计算单元，但内部调度、指令和电路组织不同。TPU 的 TensorCore 与 NVIDIA GPU 的 Tensor Core 还属于不同命名层级，不能直接比较数量。分块大小应根据具体算子、指令形状、片上容量与编译布局选择，没有适用于所有设备的统一数值。

可以分离 prefill/decode，也可以研究将 Attention 与 MLP 分配给不同资源：收益必须覆盖传输与调度成本，不能因各自瓶颈不同就推断拆开一定更快。

## 3. 六种优化，其实在解决不同问题

若有用工作为 F FLOPs、HBM 流量为 Q bytes，算术强度 I=F/Q。峰值 P、带宽 W 给出理想时间下界 max(F/P,Q/W)。融合减少中间结果写回，分块增加数据复用，重计算用更多 F 换较少 Q；它们作用不同，不能都简化为减少乘加。

- **减少分支发散：** 同一 warp 的线程走不同分支时，可能需要分阶段执行路径。
- **低精度：** 减少字节数，并利用更快的矩阵指令；需要控制数值误差。
- **融合：** 中间结果留在片上，减少 HBM 往返和启动开销。
- **重计算：** 有时重新算一个值，比保存和重读更划算。
- **合并访存：** 相邻线程尽量访问合适的连续地址，减少无效内存事务。
- **分块：** 一次加载的数据服务多次计算，提高复用。

不要把它们简单理解成“减少 FLOPs”。重计算可能增加 FLOPs，却减少真正的瓶颈。

### 低精度、重计算与访存的具体限制

Warp divergence 会使不同分支上的线程分批执行或受掩码控制，但不是看到 `if` 就一定慢；分支是否在 warp 内一致、编译器是否谓词化都重要。低精度矩阵乘法常用低精度输入、更高精度累加；分组尺度会让转置后的分组边界不同，某些方案因此维护原布局和转置布局的量化表示，增加转换与存储开销。

低位格式需要同时理解编码与缩放。四位编码只能表示少量离散值，块缩放则用共享尺度覆盖不同数值范围；它与八位浮点格式是不同设计。缩放因子可以来自当前块统计或历史统计，不必是通过梯度训练的参数。输入/输出层等敏感位置，也应单独检查精度需求。

重计算的目的不仅是让模型装得下，也可减少中间激活的 HBM 读写，带宽受限时增加 FLOPs 仍可能更快。合并访存要结合每个 warp 的地址分布、物理布局、对齐和事务粒度；一次读取并不意味着“整行整列免费”。Tiling 的收益来自片上复用，tile 过大则可能占满寄存器/shared memory，降低并发。

### ReLU 算术强度的单位

算术强度是操作数除以读写字节数，其倒数才是 bytes/op。若每个元素读取一次、写出一次，并将一次比较计作一个操作，则 FP32 每元素传输 8 bytes，强度为 1/8 op/byte；FP16 每元素传输 4 bytes，强度为 1/4 op/byte。使用新输出张量时，每个位置都要写结果。比较是否计作 FLOP 是计数约定，整个账本应保持一致。

### 四位格式名称与块缩放

MXFP8 用分组缩放，转置后分组方向变化，所以训练配方可能从高精度源分别产生两个方向的量化表示。不能先对低精度数据转置，就默认与“转置后再量化”完全等价；量化和转置一般不交换。训练中仍可能保留一些 BF16/FP32 操作，理论位宽减半不等于训练时间减半。

要区分 MXFP4 与 NVFP4。按 [NVIDIA 对两者的官方比较](https://developer.nvidia.com/blog/train-models-faster-with-jax-and-maxtext-using-nvf-on-nvidia-blackwell/)，MXFP4 通常每 32 个元素用 E8M0 缩放；NVFP4 每 16 个元素用 E4M3，另有张量级缩放。两者都可用 E2M1 的四位元素网格，未缩放数值为 `±{0,0.5,1,1.5,2,3,4,6}`，不能把四位值网格误叫 MXFP8。选择格式时，需要同时核对元素编码、块大小与缩放层级。

### 8 次访存如何变为 5 次

未融合时，前向读 x 并写出三个 sigmoid 中间输出，共 4 次张量读写；反向读取三个所需量并写 dx，共 4 次。融合前向只读 x、写最终 out，共 2 次；反向读 x 与 dout，在片上重算中间激活，再写 dx，共 3 次。总计从 8 次变为 5 次，用额外计算换取较少数据移动。这里数的是简化的张量读写次数，真实总线事务与每次访问成本还受缓存、布局和数据量影响。

### 画出 lane 的地址再谈合并

判断合并访存，要比较同一条指令下不同 lane 的地址。对 row-major 矩阵，元素地址是 `base+(row*N+col)*bytes`。同一条 load 下，相邻 lane 读同一 row 的相邻 col，地址连续；相邻 lane 读不同 row 的同一 col，步长是 `N*bytes`。后者通常需要更多事务。每个线程自己在循环中沿行移动，并不能说明整个 warp 的同一次访问是合并的。[NVIDIA 全局访存说明](https://developer.nvidia.com/blog/unlock-gpu-performance-global-memory-access-in-cuda/)将这种合并描述为尽量少的事务，而不是任何 warp 都只发一次内存请求。

## 4. 用分块矩阵乘法理解复用

tile 是从大矩阵取出的小子块。若输出小块为 b×b，把对应两块输入读入后，可在片上反复用于 b² 个输出的计算。寄存器和共享内存不够时会降低可驻留工作或发生更慢的存储访问，因此理想复用与并行度必须一起考虑。

计算 `C=A@B` 时，朴素方法为每个 C 元素反复读取 A 的一行、B 的一列。相邻输出明明需要很多相同输入，却重复从 HBM 获取。

分块方法让一个 block 负责 C 的一个 tile，沿归约维度依次加载 A/B 的对应子块，在片上累积。若块边长为 b，每份输入可以服务约 b 次乘加，算术强度随 b 提升。

但 b 不能无限增大：共享内存和寄存器装不下，驻留 block 变少，尾块也可能浪费更多计算。选择 tile 是多约束优化，而不是越大越好。

**教学算例：** 一个 GPU 若每轮理想调度 100 个同样大小的 block，100 个 block 一轮完成，101 个就可能需要第二轮。这是 wave quantization 的直觉。真实 SM 可同时驻留多个 block，实际波次必须结合资源占用判断。

### 为什么矩阵稍大反而吞吐骤降

有两种不同的量化效应：**tile quantization** 是边缘 tile 大量位置被 mask，**wave quantization** 是 tile 数略超过一波可并发工作的容量，迫使少量尾部 tile 单独等下一波。用 98 与 120 个 tile、108 个 SM 的简化例子说明后者。现实中每 SM 可驻留的 block 数取决于资源，不能把“一 SM 一 block”当成通则。Padding 有时增加算量却改善对齐和利用率，是否有利必须测量。

### 边缘 tile 与对齐

边缘块会浪费部分计算，行首偏移还可能使同一块跨越更多访存区间。对 **256×256 的二维输出、128×128 输出 tile**，需要 2×2=4 块；两维都变为 257 时需要 3×3=9 块；若仅一维变成 257，则是 6 块。Padding 应综合额外计算与对齐收益决定。

### 吞吐锯齿图和 wave quantization

把词表大小从 50257 补齐到 50304，曾在特定实现中改善吞吐，说明形状对齐有时值得额外计算。研究矩阵性能时，可以按整除性质比较不同维度的 TFLOP/s。但吞吐表示每秒完成的工作量；问题更大、吞吐更高，并不必然意味着总耗时更短。

以 256×128 tile 为例：`ceil(1792/256)*ceil(1792/128)=98`；改成 1793 后为 `8*15=120`。若简化为每个 SM 同时处理一个块，108 SM 从一波变两波，尾波只有 12 个块。现实还受寄存器、shared memory、每 SM 驻留块数和 kernel 选择影响，因此这是解释锯齿的模型，不是所有矩阵尺寸下的精确性能预测。

## 5. Attention 的大中间矩阵

对一条序列，Q、K、V 是 query、key、value 向量组成的矩阵。先算每对位置的分数，按每个 query 对所有允许 key 做 softmax，再对 value 加权。因果 mask 排除未来。FlashAttention 保留这个数学任务，改变的是保存和搬运中间量的方式。

标准 Attention 先计算 `S=QKᵀ/√d_h`，再做 `P=softmax(S)`，最后 `O=PV`。S 和 P 的形状随 T² 增长。即使最终 O 只有 T×d_h，也可能把巨大的中间矩阵多次写回和读出。

FlashAttention 的目标是计算同一个稠密 Attention，在允许的浮点舍入差异下，避免显式保存完整的 S/P 到 HBM。它不是稀疏 Attention，也没有把所有算术量从平方变成线性。

## 6. 在线 softmax：为什么可以分块算

在线不是只看当前块，而是保存已经看过的所有块所需统计量。m 是当前最大分数，l 是以 m 为基准的指数和，a 是同基准的加权 value 和；a 可以是向量。最大值变化时，旧分母与旧分子都必须乘相同的重新缩放因子。

对已经处理的 logits，保存最大值 m 和归一化和 ​l=Σexp(s−m)。新块出现后，最大值变成 m'。旧指数和必须改用新的基准，因此：

$$
m'=\max(m,\max_j s_j),
$$
$$
l'=e^{m-m'}l+\sum_j e^{s_j-m'}.
$$

再保存未归一化的输出向量 a：

$$
a'=e^{m-m'}a+\sum_j e^{s_j-m'}v_j.
$$

全部块处理完，输出 (o=a/l)。关键不是局部 softmax 各算各的再平均，而是**持续统一指数的缩放基准**。

教学算例：第一块只有 logit 0，保存 m=0、l=1。第二块只有 logit ln2，新 m'=ln2，旧和变为 1/2，新项为 1，所以 l'=1.5。两个位置的最终权重是 1/3 与 2/3，和一次性 softmax 相同。

初始化时 m=−∞、l=0，实际实现要正确处理全遮罩行和第一次更新，避免出现 `−∞−(−∞)` 造成 NaN。

## 7. FlashAttention 把这些机制组合起来

反向传播需要前向中的若干值，通常选择保存或重算。FlashAttention 通过保存较小的归约统计并在反向重建部分分数，增加一些计算却减少大矩阵往返。精确 Attention 指实数公式保持一致；浮点归约顺序改变仍会带来舍入差异。

固定一个 Query tile，依次读入 K/V tile，计算局部 scores，应用因果 mask，用在线规则更新最大值、分母和输出累加器，最后写回结果。反向可以重新计算部分中间值，减少前向保存量。

**补充理解：** 我们并没有“忘掉”完整注意力矩阵里必须的信息，而是识别出最终输出只需要特定的归约统计量。找到这种充分的中间状态，往往比单纯减少乘加更有价值。

不同版本和硬件的具体流水、并行切分、累加精度会不同。因此性能结论要附序列长度、head dimension、dtype 和设备，不能写一个脱离环境的固定加速倍数。

### FlashAttention 的精确性说到哪一层

FlashAttention 将分块、融合、在线 softmax 和反向重计算组合起来。在线过程保留行最大值、指数和、加权 value 和；遇到更大最大值时，旧统计必须按新尺度重缩放，不能只改最大值。反向保存必要的紧凑统计，再按 tile 重算局部分数，避免存完整 T×T 概率矩阵。

它对标准 attention 是数学等价的重新组织，浮点归约顺序仍可能改变末位误差；节省 HBM 中间量不代表标准 dense attention 的 FLOPs 已变成线性。性能还受 tile 调度和硬件代际影响，不能把某张图上的加速倍数写成所有形状的承诺。

### FlashAttention 图表中的增算减 IO

一项实验从 66.6 增至 75.2 GFLOPs，却把 HBM 读写从 40.3 降到 4.4 GB、耗时从 41.7 降到 7.3 ms；这组数字说明重计算可能换来更快的实际运行，不是其通用加速倍数。

给定 Q、K、V 后，Attention 核心有两次矩阵乘法：先计算 `QKᵀ` 得到分数，再计算 `PV` 汇总 value。生成 Q/K/V 的输入投影应另行计账；输入张量的个数不等于矩阵乘法次数。

在线 softmax 不仅要维护分母，还要维护并重缩放未归一化的 value 加权和，才能得到正确输出。每个 tile 分别 softmax 后直接相加会错，因为各块的归一化常数不同。反向可以利用保存的归一化统计量重计算局部中间值，以额外计算换取较少显存占用。

## 深入算例与补充理解

### 从两块推广到任意块：在线统计为什么可靠

旧块的 a 和 l 都以 exp(−m) 为基准，新块要用 exp(−m')。把旧值同时乘 exp(m−m')，就把旧项和新项放回同一坐标系。只缩放分母、不缩放输出分子，会得到错误的结果。

这类算法的一个好处是可以把两组已计算的统计量合并，而不一定逐 token 更新。若左右两块最大值为 m1、m2，令 m=max(m1,m2)，分别缩放各自分母与分子后相加即可。因此分块顺序能够灵活安排；浮点顺序仍会引入小误差。

### T² 中间结果到底有多大

令 B=2、h=32、T=8192，单个 `[B,h,T,T]` BF16 张量容量为 8 GiB。若同时保存 scores、probabilities、dropout mask 等，远不止这一份。对比最终 `[B,T,d]`，若 d=4096，其 BF16 容量是 128 MiB。

这说明 Attention 瓶颈不仅来自乘法多，更来自中间表示远大于输入输出。FlashAttention 的巨大价值就在于改变了中间状态保存方式。这里仍不能把缓存全部历史 K/V 的成本忽略掉，那是另一项线性随长度增长的状态。

### 合并访存不等于“地址越连续越好”这么简单

对行主序矩阵，同一行相邻列通常连续，不同行同一列则隔着 stride。线程映射决定一个 warp 最终发出哪些地址。若输入转置或做了 padding，逻辑相邻与物理相邻未必相同。

还要考虑对齐、事务大小、cache 行与实际硬件访问方式。因此“我按行写代码”不是 coalescing 的充分证据；需要画出各 lane 的字节地址，再结合 profiler 看内存事务效率。

### 一个好的 GPU 直觉应带边界

融合往往减少往返，却可能让寄存器不够；低精度减少数据量，却可能引入解量化；加大 tile 提高复用，却可能减少驻留工作；重计算省激活，却可能使本来计算受限的部分更慢。

这些都可以在 roofline 与资源约束下解释。优化的正确姿势不是收集一串“总会更快”的技巧，而是先判定当前瓶颈，再预言改动会怎样改变 F、Q、并行度与峰值存储，并用数据检验。

## 独立完成一个小算例

若块边长为 128，256×256 输出需要 2×2=4 个输出块；尺寸变为 257×257 则需 3×3=9 个块。元素只多一点，调度块数却明显跳变。这解释了性能曲线为什么可能呈锯齿，而不是保证某个具体尺寸必然更慢：还取决于每个块耗时、并发和编译器。

## 8. 自测与实验

1. 用上面的两个 logits 手算在线分母和加权输出。
2. 比较 T 翻倍后朴素 Attention 的 scores 容量与 KV cache 容量变化。
3. 为什么 padding 到更规整的形状，有时会让更多计算反而更快？
4. 设计一个测试，比较朴素 Attention 与分块版本，覆盖因果 mask、非整块长度和不同数值尺度。

**参考思路：** scores 随 T²，cache 在固定模型下随 T；对齐收益需要超过填充成本；比较要用误差容限，并检查不能访问未来位置。

### 逐题推理

1. 第一块分数 0、值 2，统计为 m=0、l=1、a=2；加入分数 ln2、值 6 后，m'=ln2，l'=1/2+1=1.5，a'=1+6=7，输出 7/1.5=14/3。
2. 完整位置分数矩阵随 T² 增长，历史 KV 数随 T 增长；两者用途不同。
3. 更规整的形状可能避免小尾块和部分空闲波次，额外无效计算的成本可能小于利用率收益，仍须实测。
4. 检查因果方向、尾块、全遮罩行和大数值输入；输出与梯度都应按明确容差比较，不能仅比较运行时间。
