## 1. “训练于互联网”省略了哪些步骤

训练语料是模型实际处理的文本或其他表示，不等于某网站的全部内容。预训练通常在大量文档上预测下一个 token；token 是分词单位，训练会把看到的内容和次序转成统计学习信号。抓取、提取、筛选、去重和采样每一步都改变它看到的分布。

互联网不是一张随时可取的干净表。网页是活的服务，内容会变化，很多页面需要登录、交互或动态加载。训练管线通常经历：在线服务 → 抓取或导出快照 → 原始文件 → 文本与结构提取 → 过滤去重 → 分词与打包。

每一步都包含选择。一个 crawler 能看到什么、多久访问一次、怎样跟随链接，会改变最终分布。模型的“世界观”不仅来自世界本身，也来自收集与筛选机制。

### 网页获取与不同数据对象

Web 不是一个完整可下载的数据集。Crawler 从种子 URL 遍历链接，还面对动态内容、登录/付费墙、robots、限速、反自动化、条款以及内容权利等不同层次。抓取行为本身也消耗对方服务资源。公共 dump 往往比反复请求在线服务更合适；相同 URL 随时间或访问条件变化，不同 URL 也可能是同一内容的镜像。

## 2. 保存来源信息是一项技术能力

snapshot 是某个时点的快照，provenance 是它从哪里来、经过哪些变换的来源记录。原始压缩字节、解压字节、文档数、独立 token 数和累计采样 token 数不是同一个规模。模型训练中重复一份文档很多次，不会让原始来源数量也变多。

为每条文档保留来源 URL、抓取时间、原始快照标识、提取版本、语言、内容哈希及处理原因，能让后续实验更可解释。没有这些信息，模型表现变化时，很难区分是来源换了，还是清洗代码换了。

数据集规模应区分压缩文件字节数、解压字节数、文档数、分词后 token 数和去重后的 unique tokens。不同论文只写“TB”，可能不是同一口径。

**补充理解：** 数据来源追踪像数据库的 lineage。它既支持回放和消融，也能在发现错误样本时定位所有下游产物。

## 3. 获取、许可与使用是不同问题

许可授予特定使用条件，公有领域描述另一类权利状态，访问规则又约束如何获取服务；三者不能靠一个标签合并。集合数据集自身的说明也不必覆盖每条上游作品。课堂的个案与历史争议用于理解这些区分，不提供跨地区、跨用途的一条通用许可结论。

课堂讨论了 robots、服务条款、许可、版权与隐私。这里保留对工程决策最重要的区分：能下载不等于拥有所有使用权限；数据集的集合许可不一定覆盖每一条原始作品；公开代码也不等于没有许可条件。

不同 Creative Commons 许可存在署名、共享方式、非商业或禁止改编等差异，不能统一简化为“和公有领域一样”。本章不把课堂中对个别诉讼的讨论扩展成普遍法律结论，也不复述未经更新核验的期限与裁判数字。

工程上应记录来源与许可，处理个人信息，遵守对应访问规则。发现来源不明的“再分发数据”，不能仅因附带一个宽松标签就认为其上游权利已经得到验证。

### 不把法律背景压成一句错误结论

本讲确实花了较长篇幅讨论版权、许可、公开领域、合理使用和诉讼背景；初版只保留一句区分过于简略。应保留其概念层次：保护作品表达与保护抽象想法不同；取得副本、训练、生成输出、再分发也不是同一个行为。许可有具体条件，Creative Commons 不是自动等同进入公共领域；数据集外层许可不自动授予内部所有作品的权利。

字幕口述一个统一的“75 年”期限，不能当作通用规则；具体法域、作品类别与时间会改变结论。课堂举出的四因素框架与案件是当时的讨论背景，不能从个案推出“训练一律合理使用”或“能公开抓取就能任意使用”。这里不复述未独立核实的金额、判决状态或给出具体使用合法性的判断；保留来源/许可/获取方式记录的工程要求。若要在真实项目作权利决策，需要另行查对应时点与法域的一手资料。

许可随时间变化的追问已补入下节；原文件中的续行已全部纳入阅读。

### 权利期限、CC 与许可变更问答

课堂统一说“75 年”，不适合作通用期限。按 [美国版权局说明](https://copyright.gov/help/faq/faq-duration.html)，1978 年起创作的一般个人作品通常为作者终生加 70 年；匿名、笔名与雇佣作品通常按首次发表 95 年或创作 120 年取较短者，旧作品另有规则。这是美国的一般框架，不能拿出版年份简单减去 75 就判断某本书已进入公有领域。

Creative Commons 不是公有领域的同义词：具体许可可能要求署名、相同方式共享、非商业或限制演绎，须读对应条款。课堂 30–33 分钟追问“后来改许可，旧版本怎么办”时给出的是简化看法。按 [CC 官方 FAQ](https://creativecommons.org/faq/)，CC 授权在遵守条件时不可撤回；但新内容、其他合同、授权者是否有权授权仍需分别记录。这支持保存获取日期、版本和当时许可，不支持只凭网站今天的一个标记处理所有历史内容。

课堂提到的 NYT、Bartz、Kadrey 案件属于当时的法律背景，各案争点包括获取副本、训练用途和输出等不同环节。此处保留这些问题结构，不把课堂对判决与和解的口述当作案件今天状态，也不由某一次裁判概括所有训练都被允许。类似地，“注册后才能起诉”和固定注册费是课堂简写，不能不区分作品、法域和程序而当成操作规则。

## 4. Common Crawl 不是现成的高质量文本

WARC 保存网页抓取的原始响应等信息，WET 是从网页提取的文本，WAT 一类对象则侧重派生元数据。把 HTML 变成文本已经作了选择：哪个区域是正文、表格如何线性化、代码缩进是否保留。选择便捷派生文本，意味着接受上游抽取器的损失。

Common Crawl 保存网页抓取快照。WARC 包含原始 HTTP 响应等内容，WET 是从网页提取的文本版本。把 HTML 转成文本已经是有损变换：导航、代码块、表格、脚注与正文顺序可能处理不好。

直接用 WET 更方便，自己处理 WARC 则拥有更大控制权。是否保留表格、是否丢掉乱码页面、是否保留正文周围的标题，都可能改变下游效果。

网页也存在大量重复：同一个站点的不同 URL、镜像、不同日期快照、带少量变化的模板页面。未经处理的大规模并不等于丰富的信息。

Common Crawl 的 WARC 保存抓取记录，WET 是提取后的文本，二者不能混称；提取器会改变导航、正文、表格、数学和代码的保留程度。Wikipedia 的周期 dump、GitHub 的代码/提交/issue/PR 与事件元数据、arXiv 的 PDF/LaTeX/元数据，都需要不同的解析。Wikipedia 看似高质量，也可能把抓取时刻的污染保留下来，不能只因来源有编辑治理就假定完全无毒。

## 5. 专门来源各有什么价值

代码仓库包含文件及版本历史，事件归档记录 push 等事件，两者不能当成相同对象。论文可以来自 PDF，也可来自更结构化的源格式；图书还可能先经过扫描和 OCR。来源名称只能说明大类，无法单独保证每条文档质量与使用条件。

| 来源 | 可能提供的能力 | 特别要检查的偏差 |
| --- | --- | --- |
| Wikipedia | 百科式事实与规范解释 | 编辑分布、覆盖不均、特定时点的污染 |
| 代码仓库 | 语法、程序结构与工程模式 | fork、复制、生成文件、版本与答案泄漏 |
| arXiv 等论文来源 | 技术概念、数学和长文档 | PDF 提取错误、公式、重复版本 |
| 图书与长文 | 叙事、篇章与长距离结构 | 来源权限、扫描质量、版本重复 |
| 问答社区 | 问题—解释的组织形式 | 投票偏好、过时答案、模板化内容 |

一个来源“通常质量高”，不意味着其中每条内容都可靠。高质量站点也可能在快照时包含错误、破坏性编辑或自动生成内容。

### 数据对象、单位和链接要核对

Common Crawl 的累计抓取记录不等于不同网页数，更不等于互联网覆盖率；同 URL 可多次抓取，不同 URL 可给出相同内容。课堂 3–5B 的一般月度描述与 April 2026 的 2.19B 是不同口径/具体批次，不能视为一个固定数。“WARC/WET 两种格式”只是在本讲挑出两个讨论对象，并非归档体系只有这两种格式。

代码讲义的 GitHub Archive 链接误指向 arXiv S3 帮助页，正确项目入口是 [GH Archive](https://www.gharchive.org/)。事件流不是每个仓库完整历史、所有评论正文与任意私有数据的替代品。Software Heritage 文件量、BookCorpus 书数等课堂统计没有在本轮独立重建，不作为今天规模或精确数据清单。百科、论文、代码等都是有来源边界的数据，并非“高质量”标签自动担保内容真实或获得权利。

## 6. 经典数据集展示的是不同选择机制

这些数据集的名称代表一套收集和处理决策。复现一条公开配方，不等于得到了作者当时完全相同的数据；网站变化、过滤器版本、许可排除和去重单位都会带来差异。比较时应同时保留输入来源与最终训练采样。

WebText 用社区外链作为质量代理，OpenWebText 尝试复现类似思路；CCNet 利用语言识别和语言模型分数处理抓取语料；C4 等管线使用一系列规则过滤；The Pile 混合多类来源；Dolma、FineWeb、DCLM 等进一步公开或研究大规模清洗方案。

这些名字不只是“更多数据”的代号，而是不同的收集、筛选和混合决策。例如以百科文本为目标训练质量分类器，可能更偏好百科风格；用社区投票作信号，则会继承社区用户的兴趣。

CommonPile 一类项目强调更明确的数据许可来源。这回答的是不同约束下能构建怎样的数据集，不应仅按总体规模与另一种来源策略排名。

### 数据集演化保留哪些信息

| 路线 | 课堂要你注意的选择 |
| --- | --- |
| BERT / BooksCorpus | “免费阅读”不等于获得训练和再分发许可；长连续文本与早期句子级数据不同 |
| WebText / OpenWebText | Reddit 外链及分数是质量代理，不是随机互联网采样；开源复现与原数据也不必完全相同 |
| CCNet | 去重、语言识别、参考语料训练的语言模型打分，用于多语言筛选 |
| C4 | 从 Common Crawl 用启发式清洗；去掉含代码符号的页面等规则，会改变学到的能力 |
| GPT-3 | Common Crawl、WebText、书籍、Wikipedia 混合；部分来源未公开，不能把名称当成完整可复现配方 |
| The Pile | 多来源社区整理，含论文、代码、问答等；Books3 等上游选择也会沿复用链传播 |
| Gopher / Llama / RedPajama | 自有抓取、网页规则、Wikipedia 及引用页分类、代码许可与论文格式处理等不同决策 |
| RefinedWeb / FineWeb | 以网页清洗和去重为核心，说明高质量网页本身可以很有用；“web-only 有效”不证明其他来源无价值 |
| Dolma / DCLM | 多源处理与模型筛选；正例定义了分类器的“好”，大原始池过滤后可能只剩很小比例 |
| Nemotron 类数据 | 教育价值/质量评分，部分低质文本改写成百科风格，高质文本生成任务；同时改变数量、分布与监督形态 |
| The Stack / Stack v2 | 许可筛选、去重、隐私处理之外，还处理代码事件、差异与上下文、文档、低资源语言及中间表示等 |
| 严格许可来源路线 | 从逐项来源查起；数据集整体的许可声明不能自动覆盖其中每篇作品；来源合法性还要沿上游核实 |

数字规模应区分唯一文本、tokenizer 后的 token 数、去重后量和多 epoch 处理量。网页池再大，真正保留量和有效信息也可能有限。代码中的一行 diff 如果没有足够周边上下文，可能无法形成有意义训练样本；反之整仓库打包会付出更长上下文成本。Stack Exchange 的问答/投票与软件协作记录，说明预训练语料也可自然含任务结构。

### 数据集比较不能只看一个 token 数

LLaMA 的质量分类代理是 Wikipedia **引用的页面**，与 CCNet 的 Wikipedia 语言模型相似度不是一个目标。DCLM 把 RefinedWeb 作为对照分布的负例，含义是“相对正例的分类标签”，不是逐条证明这些文本低质。规则过滤也会定义偏好：丢弃含花括号、短句或特定词的文档，会影响代码、语言风格与领域，不能说避免神经分类器就没有偏差。

Nemotron 的改写可能改善表达，也可能改变或编造事实；生成问答使文本变成不同监督形态，不是无损扩充。比较数据量时同时列来源文本、独立 token 量、抽样/重复训练 token、保留率与训练预算，不能把 3.8T 的语料与 15T 的训练消耗简单排大小。

The Stack v2 的代码数据与使用它的 StarCoder2 **整体训练配方**需要区分；讲义合并讨论的额外网页、问答、LLVM 成对语料，不表示每项都作为同一种 The Stack v2 原始仓库对象。PR 线性化要显式决定 diff、文件上下文、评论与时间边界，未来补丁不能悄悄变成评估时已知上下文。CommonPile 的许可来源检查同样不等于只看集合页许可证；底层作品和许可授权链仍是其要解决的问题。

## 7. 为什么质量分类器总在定义“好”

质量分类器学习把某种目标样本与背景样本区分开，输出只是“像目标数据”的代理。若正例是百科风格，它可能偏好百科表达；模型级消融才进一步回答这些保留样本是否改善目标任务。低分不自动表示事实错误，高分也不保证无污染。

“好数据”必须相对于目标来定义。规范百科文章对事实问答有价值，但可能缺少口语、多语言方言或真实代码调试过程；一本排版漂亮却抽取错公式的教材，未必是高质量数学数据。

因此数据评估需要两层证据：文档级抽检，检查实际留下什么；模型级消融，检查在固定预算下改善哪些能力。分类器分数只是代理，不是训练效用本身。

数据管线还需要监控长尾：某些语言、少数群体表达和特殊领域的文本，可能因不符合主流写作风格而被过度过滤。

## 8. 从预训练到后训练，数据形态会变化

SFT 是在指令与示范回答上监督学习，偏好数据比较回答好坏，环境轨迹记录模型行动及反馈。它们与网页文档的目标不同，不能因为格式都能转成文本，就认为混入同样比例一定产生同样行为。

预训练主要学习广泛文档分布；mid-training 常提升某些领域或能力；后训练使用指令、对话、偏好与环境轨迹。边界并不总清楚，但训练越接近产品行为，数据通常越需要明确的任务与反馈。

这也解释了为什么“同一个模型结构”可以产生不同能力：数据的分布、顺序和目标才决定模型实际上练习了什么。

## 深入算例与补充理解

### 一个来源怎样变成训练样本

设某网页含有标题、导航、正文、代码和评论。原始 WARC 保存抓取时的响应；抽取器把正文和代码转换为文本；语言识别器判断正文语言；规则与分类器筛选质量；去重器删除镜像；tokenizer 编码，再由打包器把多个文档装进固定长度序列。

如果最后训练效果异常，可以沿这条链回查：是不是导航被误认作正文？代码缩进丢了？评论与正文被混在一起？重复镜像权重过高？文档边界 token 丢了？这比笼统说“Common Crawl 太脏”更能指导修复。

### 文档边界也是一种监督

把两篇无关文档直接连接，模型可能被要求用前一篇末尾预测下一篇开头。是否加入 EOS、是否重置位置、是否使用文档间 Attention mask，都会影响这个学习目标。

没有一种打包方式对所有任务都最佳。例如跨文档连续 Attention 更容易实现，但可能引入无意义上下文；严格分块 mask 减少干扰，却需要对应高效 kernel。数据打包与系统实现也会相互约束。

### 质量代理为什么需要抽样审计

假设过滤器把含“参考文献”的文档打高分。一开始它可能很好地区分严肃文章与垃圾页面；但某些自动生成网站也有大量伪造参考文献，于是同一特征不再可靠。

这是一种分布变化问题。应按分数区间抽样，而不只看最高分的漂亮例子；记录误保留和误删除，并分别观察语言、来源和时间。总体准确率很高，也可能掩盖一个重要领域被全部删除。

### 数据消融应怎样控制成本

若数据 A 训练 100B token、B 训练 10B，A 的效果更好，不能据此说来源 A 更优；若按相同原始字节数比较，两者 tokenizer 紧凑程度又可能不同。一般应先确定固定的是训练 FLOPs、有效 token 数还是独立文档量。

可执行的基础对照是：同一模型、相同 tokenizer、相同训练预算与评估集，仅改变一个来源或处理步骤；若改变来源导致重复率不同，再单独解释重复效应。来源价值本来就与预算和混合上下文有关，不必追求一个脱离条件的永久排名。

## 独立完成一个小算例

来源 A 有 10B 独立 token，来源 B 有 100B。若训练总预算 200B、各采一半，A 要重复 10 遍，B 为 1 遍。即使配比都是 50%，模型得到的独立信息与重复强度并不对称；这把“来源清单”接到了下一讲的数据管线问题。

## 9. 自测与实践

1. 随机抽查 20 条提取文本，分别标记正文错误、重复、模板、语言误判和来源缺失。
2. 为一个代码仓库定义去重单位：文件、函数还是仓库？说明会漏掉什么。
3. 为什么 Wikipedia 分数高的页面，不一定最有利于你的目标任务？
4. 设计一个数据 manifest，支持未来重新抽取和追踪每次过滤原因。

**参考思路：** 先让数据流程可追踪，再讨论规模；对模型效用的结论必须有与目标相符的评估。

### 逐题推理

1. 用固定抽样规则记录每类问题，保留来源与处理版本；20 条只能提供局部诊断，不代表全库错误率已精确估计。
2. 文件级会漏跨文件局部复制，函数级可能误合并上下文不同代码，仓库级会漏 fork 内的小改动；单位需匹配目标。
3. 百科风格得分衡量代理分布相似性，目标任务可能更需要对话、代码或某领域知识，应通过固定预算消融检验效用。
4. manifest 可记录来源 URL、快照、抓取时间、内容哈希、许可说明、提取器版本、语言、每步保留/剔除理由及下游标识，支持重跑和回查。
