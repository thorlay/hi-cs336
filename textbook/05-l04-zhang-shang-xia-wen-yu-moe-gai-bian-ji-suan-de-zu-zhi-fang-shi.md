# L04｜长上下文与 MoE：改变计算的组织方式

## 1. 两种不同的“大”

序列更长，Attention 需要处理更多位置关系；参数更多，MLP 需要更大容量。本讲分别处理这两件事：线性 Attention 等方法改变历史信息的保存与访问方式，MoE 则让每个 token 只调用一部分参数。

两者都希望更省计算，但代价不同。压缩历史会限制可保留的信息；选择专家会引入路由、负载均衡和跨设备通信。不能只比较理论 FLOPs。

## 2. 从矩阵结合律走到线性 Attention

忽略 softmax，令 `Q,K[T,d_k]`、`V[T,d_v]`。表达式 `(QKᵀ)V` 可以重排为 `Q(KᵀV)`。前者先产生 T×T 的矩阵，后者先产生 d_k×d_v 的矩阵。当特征维度固定时，后者对 T 的依赖是线性的。

关键限制是：**一般不能把 softmax 直接穿过结合律。** `softmax(QKᵀ)V` 不等于 `Q(KᵀV)`。线性 Attention 改变了相似度函数和归一化方式，不是对标准 Attention 无损换一种计算顺序。某些方法使用核特征映射，还需要对应的归一化分母。

## 3. 历史可以保存成一个状态矩阵

对于因果形式，定义：

$$
S_t=S_{t-1}+k_tv_t^\top,\qquad y_t=q_t^\top S_t.
$$

S 的形状是 d_k×d_v。每来一个 token，把 key-value 外积写入状态，再用 Query 从状态读取。于是推理时不用保存全部历史 K/V，状态大小不随 T 增长。

**补充理解：** 标准 Attention 像保留每份原始档案，检索时逐条比对；状态模型像持续更新一张统计表。统计表紧凑，但不同历史可能压缩成相同状态，因此精确找回某条很早的信息可能更难。固定状态不是免费获得无限记忆。

## 4. 衰减、门控与 Delta 更新

若旧信息不断累加，状态可能拥挤。加入 ​(S_t=\gamma_tS_{t-1}+k_tv_t^\top) 后，模型可以控制遗忘。课堂以此解释 Mamba-2 等结构的部分机制，但完整模型还有投影、卷积和训练算法，不能把它等同于这一行公式。

Gated DeltaNet 的思想进一步引入选择性擦写：沿当前 key 方向删除一部分旧内容，再写入新 value。课件给出的简化状态更新为：

$$
S_t=\gamma_t(I-\beta_tk_tk_t^\top)S_{t-1}+\beta_tk_tv_t^\top.
$$

其中 key 的尺度约束会影响更新性质。β 近零时，输入几乎不写入；γ 决定旧状态的整体保留程度。它比无条件累加有更强的记忆管理能力。

训练可以利用分块和并行扫描等算法，推理则用递推；“状态递推”不意味着训练只能串行。混合架构再穿插全局 Attention，补充压缩状态不擅长的精确检索。另一条路线是稀疏索引：先找少量相关位置，再在这些位置上计算 Attention。

## 5. MoE：增加总容量，限制单 token 工作量

MoE 通常把一个 MLP 替换为 E 个专家和一个 router。对输入 x，router 给每个专家打分，选择 top-k：

$$
y=\sum_{e\in\mathrm{TopK}(s(x))}g_e(x)\,\mathrm{Expert}_e(x).
$$

总专家参数近似随 E 增加，单 token 的专家计算主要随 k 增加。如果有 8 个专家、每 token 激活 2 个，那么专家部分只执行四分之一；但 Attention、共享层和路由成本仍然存在，不能说整个模型都只花四分之一计算。

总参数影响模型存储与部署，激活参数影响单 token 算量，实际吞吐还受跨卡通信与专家分布影响。因此介绍 MoE 时必须同时给出这几种口径。

## 6. Router 为什么会“偏心”

如果少数专家初期表现较好，router 可能把更多 token 分给它们；它们因此得到更多训练，其他专家更难追上。这既会降低模型有效容量，也会造成某些设备拥堵。

常见辅助均衡损失把实际分配比例和平均路由概率相乘，惩罚过度集中；也有方法动态调整专家选择偏置。离散 top-k 的选择本身不可微，但被选专家的连续权重、专家参数以及辅助目标仍可得到梯度。不要说“加了 softmax 就让 top-k 完全可微”。

均衡也不是“每条输入平均使用全部专家”。那样会失去条件计算。目标是在批量和时间范围内避免过度拥塞，同时保留输入相关的选择。

## 7. 细粒度专家、共享专家与通信

把大专家切成更多小专家，可以让路由组合更灵活；共享专家则始终处理所有 token，承担通用部分。是否有收益依赖匹配的计算预算和实验，课堂展示的模型消融并不完全一致。

专家并行把专家放在不同设备上：先 dispatch token，再执行各专家的矩阵乘法，最后 combine 输出。这个过程经常涉及 all-to-all。激活专家更多、路由跨节点更散，都可能让省下的计算被通信抵消。

容量有限时，一些实现会丢弃超额 token。这使某个 token 的路径受同一 batch 中其他 token 影响，出现额外的批次依赖。无需容量丢弃的实现可以缓解这种问题，但仍要考虑数值和调度差异。

## 8. MLA、upcycling 与多 token 预测

MLA 把 K/V 表示成较低维潜变量，缓存潜变量而不是所有展开的 K/V。部分投影可通过代数吸收，但 RoPE 会使吸收更复杂，因而需要区分可压缩部分和位置相关部分。

Upcycling 用已训练的 dense 模型初始化多个专家，再继续训练分化；复制权重本身并不产生新知识。多 token 预测则增加预测未来多个位置的训练目标，也可能为推理阶段的候选生成提供辅助。

## 深入算例与补充理解

### 用两次写入看状态冲突

设 key 只有两个方向。第一次写入 k=[1,0]、v=3，第二次写入同一个 key、v=5。无遗忘的线性状态会沿这个方向保存两次贡献的和；用相同 Query 再读，会倾向读出 8，而不是自动理解“最新值为 5”。

这并不是说线性 Attention 必然算错，而是在提醒：最简单的外积累加没有“替换旧条目”的语义。模型需要通过门、衰减、Delta 更新或其他表示学习机制处理冲突。选择性擦写的价值由此变得直观。

### 总参数、激活参数与设备负载

假设每个专家 100M 参数，共 16 个专家，每 token 选 2 个；专家总参数 1.6B，而每 token 的专家激活参数 200M。若有四张卡，各放四个专家，理想均衡时每张处理相近数量 token。

但是一批 1000 token 若有 700 个都选择同一组专家，这些专家所在卡会排队，其他卡可能空闲。总体平均每专家 125 次激活并不能说明最大负载是多少。训练步通常受最慢卡约束，因此应报告 load 分布、最大/平均比和通信等待。

### 路由梯度到底流到哪里

在一个简单 top-2 router 中，选择集合在局部参数变化下常保持不变，选中专家的 gate 权重可微，其内部网络也可微；未选专家通常没有本次 token 的专家梯度。集合切换处则存在离散不连续，这与一个完全光滑的 dense softmax 混合不同。

负载辅助目标可以利用所有专家的连续概率，帮助未被选中的方向得到路由信号。但它不等于让所有专家都执行前向，也不意味着离散选择已经得到精确梯度。把训练路径逐条画出来，比笼统说“端到端可训练”更能解释机制。

### 三种公平消融怎样安排

若比较 MoE 与 dense，可以固定总参数，问条件计算的效果；也可以固定激活 FLOPs，问增加未激活容量的收益；还可以固定端到端训练时间，问系统成本后的真实效用。三种实验可能给出不同答案，而且都可以合理。

线性 Attention 与标准 Attention 的比较同样要固定上下文范围与任务。只测平均 PPL，可能看不出长距离精确检索的退步；只测一个 needle 任务，也不足以判断一般语言建模质量。

## 9. 自测

1. 为什么线性 Attention 的固定状态会影响精确检索？
2. 64 专家、top-8 改为 top-4，总参数和激活专家计算各怎样改变？
3. 为什么专家平均利用率很高，最慢的设备仍可能决定全步耗时？
4. 为 MoE 消融设计两个公平比较：同 FLOPs、同总参数。它们分别回答什么问题？

**参考思路：** 第一问关注信息压缩；第二问总专家参数不变，专家计算近似减半；第三问看最大负载和同步等待，而不只看平均数。

## Transcript 对照补遗

### 线性化、递推与稀疏选择不是同一件事（00:00–约 33:00）

课堂明确区分两次变化：**去掉 softmax 会改变模型；在线性模型内部把并行矩阵形式改写成因果递推，在相同因果约定下可以等价。** 门控若只依赖当前输入，状态更新仍可保持适合并行化的结构；这也是它们区别于一般非线性 RNN 的重要条件。Mamba-2 简化读出还含当前 value 的直通项，可写作 `y_t=q_tᵀS_t+Dv_t`（按此处向量方向约定）；这不是记忆更新的核心，却不能把它从完整模型中误删。

Delta 项 `(I−βkkᵀ)` 只有在特定归一化和 β 设定下才是严格投影，一般只是沿 key 方向削弱已有内容。类似更新也可从最小二乘、fast weights 或测试时学习角度推导，不能因为动机不同就认为运算必然不同。课堂比较的 7:1、3:1 等混合比例是具体模型配方；增加递推层可能逐步损害长上下文 QA 与精确检索，纯递推端点尤其明显。

DeepSeek Sparse Attention（DSA）先用廉价 indexer 为历史位置打分，top-k 选位置，再做较高成本 attention。Indexer 可用较低维度、较低精度减少常数，但若仍比较全部位置，其总体成本仍有二次项。选出的每个 query 只访问 k 个 key 时，主 attention 约为 O(Tkd)，不能仅因有 top-k 就说整个算法 O(T)。这与 FlashAttention 保持标准 attention 数学形式、优化读写的路线也不同。

课堂提出的训练路线为短上下文预训练→长上下文扩展时引入/训练 indexer→后训练，不是对任意模型直接插入一个未训练的索引器。关于未来是否取代全 attention，讲者没有确定预测，而提到检索、上下文压缩和多种架构可能结合；教材保留这一不确定性。

### Router 的完整设计空间（约 33:00–63:00）

Token choice 是每个 token 选专家；expert choice 是每个专家挑 token；全局分配则优化整个 token–expert 匹配。线性打分 top-k 是课堂调查中的主流，hash routing 是重要的非学习基线，RL 路由与全局线性分配也能做，但复杂度、方差和开销更高。专家名称不应被理解成“医学专家、法律专家”：简单 router 常体现字符、标点或语言等局部路由差异。

早期 noisy routing 在分数中加噪声，帮助接近的候选得到探索机会；某些后续消融不再需要它。不要把随机扰动说成 MoE 可训练的必要条件。共享专家和细粒度划分也应分别消融：课堂对比的 DeepSeek 与 OLMo 对共享专家收益并不一致。共享专家可复制到设备上以减少通信，但会增加副本存储。

### 均衡目标的作用和系统细节（约 63:00–结尾）

以 top-1 为例，设 `f_e` 为分给专家 e 的 token 比例，`p_e` 为平均路由概率，辅助损失可写为 `λE Σ_e f_ep_e`。把离散分配视为固定时，对 `p_e` 的导数正比于 `f_e`，会更强地压低热门专家的分数。Top-k 时需说明比例的归一化约定。专家均衡不必在每批严格均匀；设备均衡还会单独约束同卡专家的总工作量。动态路由 bias 的“aux-loss-free”也不应被扩展成完全不需要任何其他均衡控制。

MoE 可以分组或分块组织专家矩阵乘法，减少大量小 kernel 的低效；它不意味着任意 MoE 自动获得硬件 2:4 稀疏峰值。课堂还举例先把待 dispatch 激活下投影，通信后在专家里处理，以较小通信向量换取结构改变。收益取决于拓扑、批量和实现。

Capacity 超额时丢弃的是该 token 的专家计算/贡献，不一定删除整个序列 token；其他请求的路由因此可能影响当前结果。Dropless 实现缓解容量丢弃，不等于所有并发推理都严格确定。Router 的 FP32 计算与 z-loss 用于数值稳定；微调时大量专家参数又可能过拟合，可比较只调 attention、非 MoE 层或增加数据。

Upcycling 是复制 dense MLP 并初始化 router 后继续训练，不是直接获得免费性能。课堂的 DeepSeek 演化主线为：V1 细粒度+共享专家，V2 加强设备/通信均衡，V3 调整路由均衡并加入 MLA、MTP 等设计。MTP 多预测几个未来目标不消除自回归依赖，其推理收益还依赖候选验证机制。

## 逐页核验补充

### 混合模型的图不能证明纯线性复杂度

p6、8、10 的模型图同时画出低成本模块和全注意力模块。只要全注意力层数随模型规模固定且不为零，完整模型关于上下文长度仍有二次项。某个范围内的 FLOPs/吞吐曲线更平缓，说明这段范围内更省，不等于渐近复杂度已经变成纯线性。p11 的横轴增大表示递推层相对于全注意力层更多，纯递推端点在该实验的召回和 QA 上下降；不能只保留“混合几乎无损”的前半句。

p9 中 `beta=0` 使当前写入为零，但还有 `gamma*S_prev`，所以不一定完全保持原状态。`I−beta*kkᵀ` 也仅在满足合适归一化与系数条件时才是正交投影；讲者约 16–18 分钟已提醒，这只是“擦除当前 key 方向”的直觉。

### 稀疏选择保留了哪些代价

p12–13 的 DSA 先用低维/低精度索引器选择历史位置，再在候选集合上执行主 Attention。主注意力不再遍历全部 KV，并不等于索引器没有遍历全部位置；约 26–29 分钟问答明确确认索引仍是二次成本。对每个 query 选 k 个历史位置时，主 Attention 可按 `O(nk)` 而不是 `O(n²)` 计账，另加索引成本，不能把“在较短集合上二次计算”的口头比喻当作精确复杂度公式。

p13 的 RULER 表还区分只训练索引器的 warmup 与联合适配：插入索引器不是零成本地改模型，适配步骤会影响结果。字幕里“发出一个 key/value”的表达不准确，Attention 的输出是对选中 V 的加权汇总。

### MoE 对比图的四个横轴

p16–23 混合了总稀疏参数、激活参数、训练 token 和训练时间的比较。固定激活专家大小/数量时，增加总专家数可以增加容量；仍需存储更多权重，router 和通信也有开销。p17 的 7 倍与 OLMoE 的约 2 倍加速来自不同模型和实验，不是 MoE 的统一加速率。p18 的跨模型 MMLU 散点图、p20–23 的榜单还混合数据与训练配方差异，只能支持竞争力观察，不能单独量化架构因果收益。

### top-k 的顺序、权重与梯度

p31 写出先对全部专家 softmax，再只保留选中权重；另一种是选中后重新归一化。两者的非零权重和一般不同。尤其 k=1 时，若对唯一选中 logit 单独 softmax，其权重恒为 1，主任务无法经这个权重学习 router。不能只写“softmax 让任意 top-k 路由都自动学会排名”；应说明使用全专家概率、选中集合中的连续权重以及辅助目标中的哪条梯度路径。

### 共享专家的消融存在分歧

p33 的 DeepSeek 消融显示共享专家与细粒度划分有收益；p34 的 OLMoE 消融则支持细粒度专家，却没有明显支持共享专家。两页应一起读，不能把共享专家写成必然提高质量的定理。p35 的 routed、active、shared 分别是可路由总数、每 token 选择数和常开数；比较预算时还需乘上各专家宽度。约 57 分钟问答指出，共享专家可复制到设备以减少通信，但会占用更多显存。

### 噪声、离散选择与截图不一致

p37 的 REINFORCE 结果说明路线可行，但梯度方差和实现成本使其未形成明显优势。p38 的高斯扰动能改变近似打平的路由顺序，给其他专家机会；它没有把 top-k 的离散边界自动变成普通可微函数。

p39 文字与口述称均匀**乘性**扰动，但投影截图显示 `router_logits += random_uniform(...)`，是加性表达；两者不一致。教材分别描述噪声设计思路，不把此截图当作可直接复现的乘性 jitter 实现；具体复现需回查原实现。

### 均衡损失、设备目标与偏置

p40 的 `L_aux = alpha*N*sum(f_i*P_i)` 中，`f_i` 是硬选择的频率，`P_i` 是平均软概率；常见处理将硬计数视为固定量，从 P 分支回传。对单个 `p_i(x)` 的偏导是 `alpha*N*f_i/T`，再经过 softmax 的 Jacobian 才成为 logit 梯度。因此“热门专家被更强压低”是方向直觉，不是对每个 logit 的完整导数。

p41 的每设备目标与每专家目标可有不同权重。严格均匀且专家均分设备时，前者会随之均匀；实际不必为此强迫每个专家完全均匀，约 69–71 分钟问答说明了额外设备约束的理由。p42 的偏置主要改选中集合，混合权重可仍取未加偏置的 affinity；“auxiliary-loss-free”也不能抹去本页明确保留的序列级辅助损失。p43 应同时看 loss 和专家负载：缺少均衡时许多参数没有得到有效训练，而不只是运行速度变慢。

### 容量限制导致批次依赖

p44–46 的 dispatch/combine 在设备间搬运激活；把激活先降维可减少通信字节，但也改变表示和增加投影成本。MegaBlocks 的块稀疏组织解决各专家 token 数不同的问题，不能直接等同为所有 GPU 都对这种稀疏提供相同硬件加速，也不等于固定 2:4 权重稀疏。

p47 描绘有容量上限的专家：同一 batch 中其他请求可能挤掉本请求的专家计算，使输出依赖批次组成。dropless 执行能消除这一类丢弃，仍不意味着浮点归约、随机采样等其他非确定性也全部消失。

### router 数值误差与 z-loss

p48 的例子有十个 logit=128，另一个=128.5。后者概率原为 `exp(0)/(10*exp(-0.5)+1)≈0.142`；如果低精度舍入使它也变成 128，就成了 `1/11≈0.091`。减最大值能稳定指数计算，却不能恢复此前已丢失的 0.5 差异。FP32 router 与 z-loss 分别减少舍入问题、约束 log-partition 尺度，不能互相替代。p49 移除 z-loss 的尖峰实验同时报告下游分数，用于说明稳定性会影响最终可用性。

### 小数据微调与 upcycling

p50 的稀疏模型训练分数继续上升、验证分数停滞或下降，是过拟合的证据；选择非专家层或 Attention 微调，以及增加高质量数据，都是讨论的办法。1.4M SFT 是一个配方实例，不是消除过拟合的通用阈值。

p51–53 的 upcycling 复制预训练 dense 权重，包括多份 FFN，再训练 router 和专家。图中的比较横轴包括额外训练时间；复制本身不会凭空带来收益。专家通过不同 token 的梯度逐步分化，而非复制时已经获得不同知识。

### DeepSeek 配置中的课件疑点

p56 标题是 V3，正文版本标签仍写 V2；专家数写 258，而 p35 同讲表格写 256。教材保留这两处课件内部不一致，不将 258 作为可靠配置。该页公式先 sigmoid 得到非负 affinity，再对选中权重除以其和；这一般**不等于对原 logits 直接 softmax**。“Sigmoid+Softmax”的标题简写不能代替公式。

p57–58 的 MLA 图还缓存旋转用的位置 key，因此“只存 latent c”是忽略位置分支的简化说法。RoPE 的旋转依赖相对位置，使上投影不能像无位置情形那样全部吸收进一个固定矩阵。p59 的 MTP 辅助目标与推测解码的验证机制也应分开：预测远一点有助于训练或提供草稿，但不自动保证草稿正确；图能画多个辅助深度，不代表课件中的实例实际训练了相同数量。
