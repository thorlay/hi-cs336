# L16｜RLVR 与 GRPO：怎样从可验证结果中学习

本章只需要基本 Python、矩阵运算和概率/求导知识，新的术语会在使用时解释。我们先逐步展开 PPO 和其实现，再说明 GRPO 的组内比较及偏差，随后按 R1、Kimi、Qwen 与 Agent 案例讨论配方和系统。

## 1. 为什么可验证反馈很有吸引力

可验证奖励指根据答案、测试或检查器给出反馈，而不只比较文风。策略 π_θ 是模型对下一 token 的条件分布；一次回答是多次 token 决策形成的轨迹。题目、工具环境与验证规则共同决定实际奖励，存在验证器不代表奖励无漏洞。

数学题最终答案、程序测试、形式证明检查，都能提供比一般聊天偏好更直接的反馈。但“可验证”也有程度差异：形式证明检查器、有限单元测试、字符串答案匹配和模型判卷，可靠性并不相同。

RLVR 的机会是让模型自己尝试多个解法，再根据结果强化更成功的行为。它的风险是模型优化的是检查器实际给的分，而不是研究者心里完整的能力定义。

## 2. 把生成看成一串决策

状态 s_t 可以取当前题目与已生成前缀，动作 a_t 是下一 token，奖励 r_t 是该步给出的反馈。回报 R_t 是从此处向后的奖励总和，若有折扣 γ 则未来乘相应幂。value V(s_t) 估计这个状态下的期望回报，advantage 衡量某次行动/轨迹比这一基准好多少。

序列 logπ(y|x)=Σ_t logπ(a_t|s_t)，所以 log 概率梯度可把终点奖励传给整条轨迹，但不会自动知道哪一步推理正确。baseline 若满足动作独立等条件，可以减方差；估计时把当前样本塞进 baseline，则必须重新分析。

prompt 是初始上下文，每个生成 token 是动作，完整回答 y 得到奖励 R(y)。策略梯度的基本形式为：

$$
\nabla_\theta\mathbb{E}_{y\sim\pi_\theta}R(y)=\mathbb{E}[R(y)\nabla_\theta\log\pi_\theta(y)].
$$

而序列 log-prob 是各 token log-prob 的和。一次最终奖励会影响整条轨迹，出现信用分配和高方差问题。正确答案中的每一步未必都必要，错误答案也可能包含正确步骤。

动作无关、仅依赖当前状态的 baseline 可以减小方差而不改变期望梯度，但估计 baseline 的方法也要检查是否引入对当前采样动作的依赖。

## 3. PPO 在限制什么

PPO 即 Proximal Policy Optimization（近端策略优化）。实际 PPO 同时涉及：正在更新的 policy、生成样本的 old policy、约束偏离的 reference，以及估计价值的 critic。old/reference 不是同义词，critic 也不是最终答案的 reward model。概率比 ρ_t=π_θ(a_t|s_t)/π_old(a_t|s_t) 用于校正当前策略与采样策略的差异。

GAE 用 TD 残差 δ_t=r_t+γV(s_{t+1})−V(s_t) 的加权和估计 advantage，权重为 (γλ)^l。λ 控制使用多少未来残差信息。下面 γ=λ=1 的抵消例子是特定终止条件下的简化，不是删除价值与轨迹定义。

令 ​ρ_t=π_θ(a_t|s_t)/π_old(a_t|s_t)，A_t 是 advantage。常见 clipped surrogate 为：

$$
\min\left(\rho_t A_t,\;\mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t\right).
$$

最大化这个目标，试图避免在同一批 rollout 上把策略更新得太远。它不是把所有参数更新硬限制到某个距离，也不保证实际 KL 一定小。value model、奖励尺度、mask、终止与截断处理都会影响稳定性。

在语言模型场景，终点奖励、每 token KL 惩罚和 critic 估计需要一致地组合。实现的细节不应隐藏在“就是 PPO”这句话里。

例如 TD 残差是 `δ_t=r_t+γV(s_{t+1})−V(s_t)`。在有限、真正终止的轨迹上，若 γ=λ=1 且终点价值为零，GAE 的残差和会抵消中间的 V，得到 `A_t=Σ_{u=t}^{T−1}r_u−V(s_t)`。这解释了简化条件下 advantage 为什么是“后续回报减当前估值”，而不是“每个 token 都等于最后一个奖励”。逐 token KL 会进入相应 r_u；因长度限制而截断的轨迹也不能未经判断就把末端价值设为零。

### PPO/GRPO 的实现与梯度边界

PPO 的公式短，但实际包括 rollout、value、advantage、采样策略、参考策略、token/序列归约等部件。用 GAE 的 γ=λ=1 和不恰当的 KL 裁剪说明：某些实现选择会把算法变成另一种目标，不能只看函数名。DPO 的成对偏好假设也不能直接替代数学/代码的绝对奖励。

### PPO 实现页不能照抄成数学定义

**对整条回答评分、在终点给出**的奖励，从逐 token 时间维看是稀疏的。逐 token KL shaping 则可沿轨迹提供附加项。

Rollout 的依赖顺序是采样回答、计算策略与参考 log-prob、评分、reward shaping，再构造 advantage。不要把对 `logp-ref_logp` 逐点截为非负当作严格 KL：单次采样的 log-ratio 可以为负，期望 KL 才非负。截掉负值会改变目标，而且这种下截断没有限制正方向任意增大，不能据此保证训练稳定。

若令 γ=λ=1，在有限终止轨迹且终点价值为零时，GAE 的 TD 残差和会望远镜抵消为 `reward-to-go − V(s_t)`。这简化了估计器，并没有把所有 token 状态和 KL shaping 从实现中删除。监控训练时，应分开记录 KL、奖励模型分数与负 KL 惩罚；KL 上升不等于总回报上升，几条曲线也可能朝不同方向变化。

## 4. GRPO 怎样省掉 value model

GRPO 即 Group Relative Policy Optimization（组相对策略优化）。它对同一道题生成 G 个回答，用组均值与标准差产生相对信号，去掉额外 critic。奖励和 old log-prob 通常停止梯度，当前 log-prob 则必须保留梯度；某时刻概率比取值为 1，不表示可把整个表达式改成无梯度常数。

对同一道 prompt 采样 G 条回答，计算奖励 R_i，常见组内 advantage 为：

$$
\hat A_i=\frac{R_i-\overline R}{\mathrm{std}(R)+\varepsilon}.
$$

再把这一序列级信号用于 token 级策略目标，并配合概率比值、裁剪和可能的 KL 项。它用同题回答之间的相对表现替代额外的 value model，节省显存和训练复杂度。

教学算例：四条奖励 `[0,0,1,1]`，均值 0.5；用总体标准差 0.5 时，advantage 为 `[-1,-1,1,1]`。若全部为 0 或全部为 1，中心化后都为 0；加 ε 避免除零，并不会自动创造学习信号。实际实现还要统一总体/样本标准差的口径。

GRPO 用同题多次采样的组内奖励比较替代 value model，节省 critic 的计算与存储。若只做严格同策略的一次更新，ratio 在取值点等于 1，clipping 暂时不生效；但实现里不能把 ratio 当无梯度常数删掉而仍期望获得相同梯度。Old log-prob、奖励和 advantage 通常应停止梯度，当前 log-prob 保留梯度。

## 5. “简单”不代表目标没有偏差

无偏性问估计器的期望是否等于指定目标的梯度；它不是“训练能用”或“效果不错”的同义词。自身参与的组均值、随机标准差、按长度归约、clipping 和多轮复用，各自都可能改变估计器，因此必须先写目标，再谈偏差。

组内标准差是数据相关缩放，会改变不同 prompt 的相对权重，不能把它当成一个保证无偏的传统 baseline。组内均值包含自身样本时，也需要仔细分析估计性质；leave-one-out 是一种相关替代思路。

先去掉标准差、长度缩放和 clipping，便能看清一个具体影响：同题独立采样 G 次，令 `g_i=∇logπ(y_i)`，则 `E[(R_i−R̄)g_i]=(1−1/G)E[R_i g_i]`，因为均值中包含当前奖励自身的 1/G。用其余 G−1 条的均值作 baseline，在独立采样等条件下可以消去这个自身项；这不自动证明加入其他归约和 PPO 更新后的完整算法仍无偏。另需注意 G=1 时某些样本标准差实现返回 NaN，加 ε 无法修复 NaN。

长度归一化同样重要。按每条序列先除长度，和把整个 batch 的有效 token 一起平均，会给不同长度的正负轨迹不同权重，可能影响回答长度和训练方向。

因此分析 GRPO 时应明确：按序列还是 token 归一化？是否除组内标准差？全同奖励组怎样处理？是否截断超长回答？KL 对谁计算？不同变体不是只换一个算法名字。

严格无偏 baseline 必须满足相应条件：组均值若包含当前样本奖励，本身也与该动作相关，不能一概称为动作无关 baseline；独立样本的 leave-one-out 均值更接近该条件。再除组内标准差，会进一步改变不同题目的权重。对全对或全错的组，中心化后 advantage 为零，**不是标准差越小就必然产生无限大的更新**；混合但方差较小的组、ε 和采样规则才共同决定权重。

按回答长度平均会重加权轨迹：失败长回答的负更新可能被稀释，成功长回答又可能被压低正更新。Dr. GRPO 类修正去掉某些长度/标准差归约，并不代表所有设置下唯一正确。应明确优化的是逐序列期望奖励，还是另外定义的 token 加权目标。

### GRPO 的有限组、无偏性和长度权重

GRPO 保留 advantage，但移除**额外 critic 与基于它的 GAE**，改用组内比较。组内归一化除以的是标准差，不能直接除以方差。加 1e−4 只避免有限标准差为零的除法；若样本标准差函数在 G=1 时返回 NaN，单纯加 ε 也无效，仍需规定 G 和标准差的计算口径。

可手算组均值自身依赖的问题：同题独立同分布采样 G 次，令 `g_i=∇logπ(y_i)` 且 `E[g_i]=0`。在不做标准差和长度缩放时，`E[(R_i−R̄)g_i]=(1−1/G)E[R_i g_i]`；若用其余 G−1 条构成 leave-one-out 均值，则消去这个自身项。该推导针对这个采样估计器，不保证加入 PPO clipping、有限数据复用后仍无偏。因此，任何“无偏”结论都须说明对应的目标、采样与更新条件。

二元奖励总体标准差是 `sqrt(p(1−p))`；靠近两端而仍混合的组会受到不同缩放，但**全同奖励组的分子也是零**。长度偏置涉及梯度贡献的权重分析，不是模型在 loss 中真的对离散长度求导。正 advantage 的长回答正更新被稀释，负 advantage 的长回答负更新也被稀释；案例的总长度增长主要来自错误回答，不能把它概括为所有回答都以相同方式变长。

## 6. 从 R1-Zero 到完整后训练流程

R1-Zero、完整 R1 与蒸馏学生对应不同训练阶段和模型。冷启动用示范先教可读推理格式，结果奖励再强化可验证成功；筛选数据后监督训练以及一般偏好阶段又可能改变其他行为。pass@1 是单次表现，cons@64 是多次结果的聚合口径，不能互换。

R1-Zero 展示了直接用结果奖励训练的可能性，完整 R1 则进一步加入推理 SFT、RL、一般指令训练与偏好优化。冷启动示范可以改善可读性和格式；后面的通用训练可能提升聊天，却也要检查推理任务是否退步。

长 CoT、反思式措辞和“aha”样例不能单独证明模型发现了新算法。需要比较基础模型已有行为、训练目标的长度偏置和固定计算预算下的实际成功率。叙事性例子可以启发问题，不能代替消融实验。

### R1 的阶段与训练信号

R1-Zero 用基础模型直接做可验证奖励，完整 R1 则组合冷启动长思维链 SFT、RL、筛选后的数据、通用指令与最终偏好阶段。语言一致性、格式和正确性奖励解决不同问题。“Aha”字样或思维链变长不构成新推理机制的独立证据，初始语料习惯和长度偏置也可能解释部分现象。过程奖励与搜索也需要单独验证；尝试过某种路线，不代表它进入了最终配方或带来净收益。

### R1、Kimi 和 Qwen 的配方各有边界

R1-Zero 的 `pass@1` 与 `cons@64` 衡量不同推理预算：64 次聚合结果不能当作单次正确率。与 o1 等历史模型比较时，也应同时固定模型版本、任务与采样预算，不能将局部优势扩展为所有任务上的排序。

R1 的数据阶段应按用途区分：约 600k 推理数据中，不能将全部任务一概归为不可验证；约 200k 非推理数据补充一般能力，后续用于蒸馏的约 800k 数据与这些材料有联系，不能当作三份独立集合直接相加。学生模型也包括 Qwen 与 Llama。PRM/MCTS 未成为这套尝试的主要方法，只说明该配方中的选择，不能证明它们在所有问题上无用。

## 7. 难度、验证器与课程安排

课程安排让当前策略持续遇到能产生学习信号的题。全组都对或都错时，中心化奖励为零；选择较难题也不能难到始终找不到成功。Kimi 的目标与长度奖励、Qwen 的题目选择和思考模式控制，是不同案例的设计，不能拼成所有模型通用的一条固定配方。

全做对的题组缺少相对信号，全做错的题组也可能没有信号。有效训练通常需要适当难度和覆盖，而不是只挑最难题。实际可采用的策略包括基于当前成功率调整题目分布、过滤偶然猜对的多选题，以及区分可验证和不可验证任务。

代码的测试用例不一定覆盖全部语义；数学答案等价检查也不只是字符串相等。`1/2` 与 `0.5` 可以等价，带单位、集合、区间与条件的答案则更复杂。验证器错误会成为奖励噪声，甚至成为模型利用的漏洞。

Kimi 的案例从 KL 正则化目标的最优关系出发，构造匹配关系的损失，得到与组比较相关的更新；动机与直接替换 advantage 不同，不能简单把它叫成完全同一 GRPO。它还强调减少无用长思考，但不能把失败轨迹惩罚到几乎立即终止，否则困难领域失去探索机会。

课程安排应保留“有学习信号”的题：反复全对的可移出，全错且始终采不到成功的也很难学，部分可解的问题更有效。当前策略 best-of-k 过滤会随训练改变，需记录采样预算，不能把“8 次采到至少一次”当成证明题目足够简单或必须删除。数学等价答案、格式解析、单元测试覆盖都会影响 verifier；使用模型检查答案又引回代理误差。

选择难度课程时，要区分候选采样次数、筛选次数与最终保留数；best-of-8 与采样十次不是同一个预算。只取多次全错的题也不能独自构成有效课程，因为始终全错的组缺少相对奖励信号。另一条路线从非参数最优关系构造平方代理损失，这是方法动机，不表示有限参数优化与 DPO 严格等价。

一种长度奖励使用 `λ=0.5−(len−min_len)/(max_len−min_len)`。因此零点是 **最短和最长长度的中点**，不是 batch 平均长度；答错时 `min(0,λ)` 不奖励更短的错误答案，只惩罚超过中点的长错误答案。所有长度相同时分母为零，实际实现需要另定保护。答案等价模型是带噪验证器；人工抽检数字只约束该抽检，不能保证所有数学任务正确。

把正确率与 token 长度画在双纵轴上时，两个高度不能直接相减。一组消融中 RL 优于 expert iteration，仍需按相同数据与预算理解。另一个阶段报告的 3995 是独立问题数，**不是整个后训练只有 3995 条生成轨迹**。同一个模型还可以通过提示标签切换思考模式；比较质量时要记录思考预算，并检查后续通用 RL 是否牺牲推理任务表现。

## 8. RL 与只模仿成功样本的差别

expert iteration 先采样、筛选好结果，再做监督学习；策略梯度则按相对奖励调整概率，可能对坏路径给出负向信号。比较要固定采样、验证与更新的总预算，不能只固定优化步数。

Expert iteration 先采样、选出较好回答，再做监督学习，流程直观；策略梯度还会利用相对奖励与概率比值，对失败或相对较差的路径提供不同更新。

二者的效果依赖采样覆盖、目标、难度和预算。不能从一个模型案例推出“RL 永远优于筛选 SFT”，也不能因 SFT 更简单就认为它一定达到相同上限。应在相同 rollout 成本下比较。

## 9. RL 的系统成本

Agent 在多轮状态中调用工具，环境反馈进入下一轮输入。rollout 服务偏推理，参数更新偏训练，二者需要权重版本与样本来源记录。异步提高利用率时，样本可能来自旧策略，吞吐收益要连同分布偏移检查。

rollout 是慢且长度不均的推理，更新则更接近批量训练。两个阶段的最佳引擎与并行布局可能不同；切换时要同步权重并明确策略版本。异步采样会提高利用率，也可能增加旧策略数据带来的偏差。

**补充理解：** 强化学习不只是“再加一个 loss”。它是一条采样、验证、筛选、更新的生产线，每个环节都可能成为瓶颈和错误来源。

### Agent RL 与系统扩展

长 rollout 的尾部请求会让同步训练等待；截断、排队、资源共置、权重广播和异步流水都改变系统效率，也可能带来离策略样本。训练与推理融合不是简单把两个服务放在一起。

Qwen 的案例还包括思考/非思考模式融合、以控制 token 提前终止并给答案，以及预算变化下的质量曲线；这是特定训练证据，不保证任意中断都能正确回答。Agent 训练可先做仓库/PR/文档/交互轨迹的 mid-training，再分别训练专门能力并蒸馏回统一模型。环境与数据往往比更换一个 RL 公式更重要。

可验证不代表不可钻空子：Git 历史泄漏未来补丁、访问远端或修改环境、形式验证系统的绕过入口，都可能让“通过”偏离真正解题。因此要审计奖励与环境边界，不能因测试/编译器存在就保证正确；在训练过的环境上进步，也不自动证明跨环境泛化。相关案例仍须连同其奖励、数据和预算条件理解。

### Agent 专家是训练分支，验证器也需要验证

**Qwen3-Coder-Next** 使用的专家分支，应与 MoE 的层内专家区分：分别训练的完整模型分支，可以通过响应数据蒸馏为最终模型，这既不是逐 token 的层内路由，也不是直接平均参数。蒸馏还要选择向各分支提问的 prompt 分布，决定最终学生覆盖哪些任务。

仓库拼接、PR 检索上下文、文本代码网页、合成轨迹、指令与 fill-in-the-middle，解决不同的数据覆盖问题。约 800k 任务环境不等于同样数量的独立人工标注 issue；70.6% 的 SWE-bench Verified 结果也需要结合具体框架理解，不能当作普适代码正确率。如果系统通过检索获取隐藏答案，分数可能异常跃升而没有真正学会解题。形式证明工具同样需要约束证明入口与评估环境，“有编译器”不能替代完整的验证协议。

安排后训练阶段时，还要注意：mid-training 是否关键取决于预训练覆盖和后续 SFT；long-CoT SFT 与长上下文扩展并非同一个阶段；推理任务与通用偏好任务常分阶段处理，后训仍可能遗忘，应看独立评估。因此，应按数据覆盖与独立评估选择阶段顺序。

## 深入算例与补充理解

### 一步梯度为什么能奖励整条轨迹

序列概率为各 token 条件概率的乘积，取 log 后变成和，因此 `R * log π(y)` 的梯度会沿所有 token 的预测路径反传。高奖励轨迹中的动作更容易被强化，低于 baseline 的轨迹则可能被压低。

但这不是逐步骤正确性监督：最终答对可能只是猜中，某些中间推理可能错误。结果奖励与过程监督回答不同的问题，不能仅凭模型写出了漂亮推理，就判断每一步都对最终成功有因果贡献。

### 同样的奖励差，标准差归一化会怎样改变权重

两个 prompt 的奖励分布不同，组内 std 也不同。除以 std 后，相同绝对奖励差可能产生不同 advantage，进而改变这些题对总更新的贡献。对二元奖励，全易或全难的组又常常归零，不是“std 小所以一定大梯度”。

这也解释课程对 GRPO 的审慎分析：需要同时讨论有限组采样、中心化、方差缩放和零方差处理，而不是单独拿一个连续总体公式给所有题下结论。

### 终止与截断有什么不同

模型输出正确结束标记，和达到最大长度后被系统强行截断，是两个事件。截断回答可能还未给出最终答案，奖励、mask 和长度归一化如何处理，会显著影响策略。

若简单把超长回答全判错，模型可能学到更短，但也可能放弃需要长推理的难题；若不限制长度，少数长轨迹会占据大量推理时间。应记录截断率、正确率和长度分布，并针对预算设计奖励与采样。

### 一个可复现的 RL 小实验应控制什么

先固定小任务、明确验证器，保存采样策略的版本与 log-prob；用固定评估集监控成功率；再逐一改变 group size、归一化与 KL。每轮同时记录独立 prompt 数、生成 token 总量和更新 token 数。

若比较两种方法只固定更新步数，rollout 长度却差数倍，实际研究费用已经不同。RL 的公平比较需要把生成成本计入，而不只是训练反向 FLOPs。

## 独立完成一个小算例

奖励 [0,0,1,1] 的总体均值为 0.5、总体标准差为 0.5，归一化 advantage 为 [−1,−1,1,1]。但奖励 [1,1,1,1] 时分子也全为零，不能声称“标准差小会产生无穷大梯度”。G=1 时若采用样本标准差，函数还可能返回 NaN；NaN 加 ε 仍是 NaN。

## 10. 自测

- `[0,0,0,0]` 的组为什么无法靠组内相对奖励区分好坏？
- PPO clip 是否等于严格 KL 约束？
- 回答变长，应该怎样区分有效计算增加与奖励/归一化偏差？
- 一个模型不断通过可见测试，却通不过隐藏测试，可能在优化什么？

**参考思路：** 同时审计目标、采样预算和验证器；正确率曲线、长度分布与未见任务表现要一起看。

### 逐题推理

1. [0,0,0,0] 中每条减去均值都为零，ε 只能保护有限的零分母，不产生区别好坏的信号。
2. clip 是局部 surrogate 的限制，不是对全部参数或实际 KL 的硬约束；仍需监控目标与采样条件。
3. 记录正确/错误轨迹各自长度、截断率和预算匹配后的成功率，才能区分有效思考与长度归约偏差。
4. 可见测试高分、隐藏测试失败可能来自覆盖不足或奖励投机；应检查验证器、环境权限及未见任务。
