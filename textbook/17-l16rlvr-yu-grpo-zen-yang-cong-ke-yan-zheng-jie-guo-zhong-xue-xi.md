# 17 L16｜RLVR 与 GRPO：怎样从可验证结果中学习

> Spring 2026 · 中文教材初版。主要依据用户提供的 `lecture-16.txt`，并结合[官方 PDF](https://github.com/stanford-cs336/lectures/blob/de53a9f979a6ee35f7d13a5e1aadee5ea1afc58e/lecture_16.pdf)。 时间定位：00:05–约 25:01 PPO/GRPO；30:01–40:00 R1；45:01–60:01 Kimi 与 Qwen；65:02–75:42 agent RL。 课件重点页：5–24、28–45、48–60（PDF 页码从 1 开始）。正文按知识逻辑重组，不是逐字翻译；“补充理解”与教学算例为作者解释。未逐句对照录音。

## 1. 为什么可验证反馈很有吸引力

数学题最终答案、程序测试、形式证明检查，都能提供比一般聊天偏好更直接的反馈。但“可验证”也有程度差异：形式证明检查器、有限单元测试、字符串答案匹配和模型判卷，可靠性并不相同。

RLVR 的机会是让模型自己尝试多个解法，再根据结果强化更成功的行为。它的风险是模型优化的是检查器实际给的分，而不是研究者心里完整的能力定义。

## 2. 把生成看成一串决策

prompt 是初始上下文，每个生成 token 是动作，完整回答 y 得到奖励 R(y)。策略梯度的基本形式为：

$$
\nabla_\theta\mathbb{E}_{y\sim\pi_\theta}R(y)=\mathbb{E}[R(y)\nabla_\theta\log\pi_\theta(y)].
$$

而序列 log-prob 是各 token log-prob 的和。一次最终奖励会影响整条轨迹，出现信用分配和高方差问题。正确答案中的每一步未必都必要，错误答案也可能包含正确步骤。

动作无关、仅依赖当前状态的 baseline 可以减小方差而不改变期望梯度，但估计 baseline 的方法也要检查是否引入对当前采样动作的依赖。

## 3. PPO 在限制什么

令 ​ρ\_t=π\_θ(a\_t|s\_t)/π\_old(a\_t|s\_t)，A\_t 是 advantage。常见 clipped surrogate 为：

$$
\min\left(\rho_t A_t,\;\mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t\right).
$$

最大化这个目标，试图避免在同一批 rollout 上把策略更新得太远。它不是把所有参数更新硬限制到某个距离，也不保证实际 KL 一定小。value model、奖励尺度、mask、终止与截断处理都会影响稳定性。

在语言模型场景，终点奖励、每 token KL 惩罚和 critic 估计需要一致地组合。实现的细节不应隐藏在“就是 PPO”这句话里。

## 4. GRPO 怎样省掉 value model

对同一道 prompt 采样 G 条回答，计算奖励 R\_i，常见组内 advantage 为：

$$
\hat A_i=\frac{R_i-\overline R}{\mathrm{std}(R)+\varepsilon}.
$$

再把这一序列级信号用于 token 级策略目标，并配合概率比值、裁剪和可能的 KL 项。它用同题回答之间的相对表现替代额外的 value model，节省显存和训练复杂度。

教学算例：四条奖励 `[0,0,1,1]`，均值 0.5；用总体标准差 0.5 时，advantage 为 `[-1,-1,1,1]`。若全部为 0 或全部为 1，中心化后都为 0；加 ε 避免除零，并不会自动创造学习信号。实际实现还要统一总体/样本标准差的口径。

## 5. “简单”不代表目标没有偏差

组内标准差是数据相关缩放，会改变不同 prompt 的相对权重，不能把它当成一个保证无偏的传统 baseline。组内均值包含自身样本时，也需要仔细分析估计性质；leave-one-out 是一种相关替代思路。

长度归一化同样重要。按每条序列先除长度，和把整个 batch 的有效 token 一起平均，会给不同长度的正负轨迹不同权重，可能影响回答长度和训练方向。

因此分析 GRPO 时应明确：按序列还是 token 归一化？是否除组内标准差？全同奖励组怎样处理？是否截断超长回答？KL 对谁计算？不同变体不是只换一个算法名字。

## 6. 从 R1-Zero 到完整后训练流程

课堂借 R1-Zero 展示直接用结果奖励训练的可能性，又讨论完整模型如何加入推理 SFT、RL、一般指令训练与偏好优化。冷启动示范可以改善可读性和格式；后面的通用训练可能提升聊天，却也要检查推理任务是否退步。

长 CoT、反思式措辞和“aha”样例不能单独证明模型发现了新算法。需要比较基础模型已有行为、训练目标的长度偏置和固定计算预算下的实际成功率。叙事性例子可以启发问题，不能代替消融实验。

## 7. 难度、验证器与课程安排

全做对的题组缺少相对信号，全做错的题组也可能没有信号。有效训练通常需要适当难度和覆盖，而不是只挑最难题。课堂案例包括基于当前成功率调整题目分布、过滤偶然猜对的多选题，以及区分可验证和不可验证任务。

代码的测试用例不一定覆盖全部语义；数学答案等价检查也不只是字符串相等。`1/2` 与 `0.5` 可以等价，带单位、集合、区间与条件的答案则更复杂。验证器错误会成为奖励噪声，甚至成为模型利用的漏洞。

## 8. RL 与只模仿成功样本的差别

Expert iteration 先采样、选出较好回答，再做监督学习，流程直观；策略梯度还会利用相对奖励与概率比值，对失败或相对较差的路径提供不同更新。

二者的效果依赖采样覆盖、目标、难度和预算。不能从一个模型案例推出“RL 永远优于筛选 SFT”，也不能因 SFT 更简单就认为它一定达到相同上限。应在相同 rollout 成本下比较。

## 9. RL 的系统成本

rollout 是慢且长度不均的推理，更新则更接近批量训练。两个阶段的最佳引擎与并行布局可能不同；切换时要同步权重并明确策略版本。异步采样会提高利用率，也可能增加旧策略数据带来的偏差。

**补充理解：** 强化学习不只是“再加一个 loss”。它是一条采样、验证、筛选、更新的生产线，每个环节都可能成为瓶颈和错误来源。

## 深入算例与补充理解

### 一步梯度为什么能奖励整条轨迹

序列概率为各 token 条件概率的乘积，取 log 后变成和，因此 `R * log π(y)` 的梯度会沿所有 token 的预测路径反传。高奖励轨迹中的动作更容易被强化，低于 baseline 的轨迹则可能被压低。

但这不是逐步骤正确性监督：最终答对可能只是猜中，某些中间推理可能错误。结果奖励与过程监督回答不同的问题，不能仅凭模型写出了漂亮推理，就判断每一步都对最终成功有因果贡献。

### 同样的奖励差，标准差归一化会怎样改变权重

两个 prompt 的奖励分布不同，组内 std 也不同。除以 std 后，相同绝对奖励差可能产生不同 advantage，进而改变这些题对总更新的贡献。对二元奖励，全易或全难的组又常常归零，不是“std 小所以一定大梯度”。

这也解释课程对 GRPO 的审慎分析：需要同时讨论有限组采样、中心化、方差缩放和零方差处理，而不是单独拿一个连续总体公式给所有题下结论。

### 终止与截断有什么不同

模型输出正确结束标记，和达到最大长度后被系统强行截断，是两个事件。截断回答可能还未给出最终答案，奖励、mask 和长度归一化如何处理，会显著影响策略。

若简单把超长回答全判错，模型可能学到更短，但也可能放弃需要长推理的难题；若不限制长度，少数长轨迹会占据大量推理时间。应记录截断率、正确率和长度分布，并针对预算设计奖励与采样。

### 一个可复现的 RL 小实验应控制什么

先固定小任务、明确验证器，保存采样策略的版本与 log-prob；用固定评估集监控成功率；再逐一改变 group size、归一化与 KL。每轮同时记录独立 prompt 数、生成 token 总量和更新 token 数。

若比较两种方法只固定更新步数，rollout 长度却差数倍，实际研究费用已经不同。RL 的公平比较需要把生成成本计入，而不只是训练反向 FLOPs。

## 10. 自测

* `[0,0,0,0]` 的组为什么无法靠组内相对奖励区分好坏？
* PPO clip 是否等于严格 KL 约束？
* 回答变长，应该怎样区分有效计算增加与奖励/归一化偏差？
* 一个模型不断通过可见测试，却通不过隐藏测试，可能在优化什么？

**参考思路：** 同时审计目标、采样预算和验证器；正确率曲线、长度分布与未见任务表现要一起看。
