# L02｜把张量、显存和 FLOPs 算明白

> Spring 2026 · 中文教材初版。主要依据用户提供的 `lecture-02.txt`，并结合[官方 课堂代码](https://github.com/stanford-cs336/lectures/blob/de53a9f979a6ee35f7d13a5e1aadee5ea1afc58e/lecture_02.py)。 时间定位：00:05–约 28:00 张量与 einops；约 30:00–55:00 FLOPs 与算术强度；60:01–77:19 梯度、状态与检查点。正文按知识逻辑重组，不是逐字翻译；“补充理解”与教学算例为作者解释。未逐句对照录音。

## 1. 先建立“物理账本”

深度学习代码看上去只是几次矩阵乘法，但机器实际要保存输入、参数、激活、梯度和优化器状态。资源核算的第一步，就是问每个数组有多大、何时创建、何时释放，随后再计算它会被读取多少次。

设张量形状为 `[B,T,d]`，元素数是 (BTd)。若使用 BF16，每元素占两字节，则容量为 (2BTd) 字节。这里的容量不等于程序峰值显存：缓存分配器、工作区、通信缓冲和算子临时数组也会占空间。

例如 `[8,2048,1024]` 有 16,777,216 个元素，BF16 数据本身占 32 MiB。同样形状改为 FP32 就是 64 MiB。这种量级估计应该先于运行大模型。

## 2. 精度：少一半字节不是免费午餐

FP16 与 BF16 都是 16 位，但分配给指数和尾数的位数不同。BF16 的指数范围接近 FP32，能够表示更大或更小的量；代价是有效精度较低。指数范围大不代表所有数都算得准，也不代表训练一定稳定。

混合精度的核心是按用途选精度：大矩阵乘法尽量利用低精度吞吐，长期累积的统计量和敏感归约保留更高精度。Adam 的一阶、二阶状态经常用 FP32；某些训练实现还保留 FP32 主权重。具体账本必须查看实际实现，不能把“每参数 16 字节”当成不可变的规则。

课堂还展示 FP8、FP4：数值更少，需要缩放、分组和相应硬件支持。只有降低存储位宽，而没有相应高效算子，不保证运行更快。

## 3. 形状是程序的类型说明

对 `X[B,T,d_in]` 和 `W[d_in,d_out]`：

$$
Y_{b,t,j}=\sum_iX_{b,t,i}W_{i,j}.
$$

结果形状是 `[B,T,d_out]`。在 einsum 的写法中，输出里消失的指标表示求和。给维度命名，比猜测 `transpose(-1,-2)` 中负数的含义更容易检查。

多头 Attention 里，`d = h × d_h` 常被打包成一个维度。`rearrange` 可以把 `[B,T,h*d_h]` 拆成 `[B,h,T,d_h]`。但“逻辑上重排”不一定是零成本：某些操作只是创建 view，某些布局会要求复制成连续存储。优化时需要同时看形状和 stride。

## 4. 为什么一次矩阵乘法约为 2mnk FLOPs

对于 `A[m,k] @ B[k,n]`，输出有 (mn) 个元素，每个元素计算长度 (k) 的点积，需要约 (k) 次乘法和 (k) 次加法，因此总量近似为 (2mnk)。FLOPs 表示工作量，FLOP/s 才表示速度。

反向为什么更贵？若 (Y=XW)，输出梯度为 (G)，则：

$$
\nabla_XL=GW^\top,\qquad\nabla_WL=X^\top G.
$$

前向有一个矩阵乘法，反向有两个相近规模的矩阵乘法。因此，参数矩阵乘法占主导时，每个 token 的训练成本约为前向三倍，常用粗估是 (6ND)，N 为参数量、D 为训练 token 数。

这个公式忽略了长上下文 Attention、重计算、优化器更新和其他开销；稀疏 MoE 更需要区分总参数与激活参数。它是估算起点，不是计费仪表。

## 5. Roofline：算得慢，还是搬得慢

设计算量为 F、需要搬运的字节数为 Q，机器峰值计算吞吐为 P，带宽为 W。理想化下：

$$
t\ge\max(F/P,\ Q/W).
$$

定义算术强度 (I=F/Q)，就得到性能上界：

$$
\mathrm{FLOP/s}\le\min(P,WI).
$$

I 低时机器等待数据，是 memory-bound；I 高时主要等待乘加，是 compute-bound。真正的耗时还可能受启动、依赖和同步影响，所以这是上界，不保证达到。

教学算例：对 n 个 BF16 元素做 ReLU，粗略算 n 次操作，读写共 4n 字节，I 约为 0.25 FLOP/byte。对 n×n BF16 方阵相乘，理想仅读两个输入、写一个输出，I 约为 n/3。矩阵越大，数据复用越充分。

**补充理解：** 同一块权重若服务很多行输入，就像一次把材料运到车间，连续生产很多件产品；单条输入却可能搬来整块权重，只加工一件。后者就是小 batch 推理容易受带宽约束的原因。

## 6. MFU 应该怎样读

MFU 通常用模型的有效 FLOPs 除以总耗时和设备峰值 FLOP/s。它会受到公式口径、精度、稀疏/稠密峰值选择以及通信开销影响。

因此“某模型 MFU 更高”必须附相同的计算口径。把硬件支持的稀疏峰值拿来衡量稠密计算，会人为拉低利用率；把重计算也算成有效模型工作，则可能人为抬高数字。

## 7. 显存不足时，两种不同的交换

**梯度累积**把一个有效 batch 拆成多个 microbatch。每次保留较少激活，累积梯度若干次后才更新参数。不应每个 microbatch 都清零。若每块损失已经取平均，等大小 K 个 microbatch 通常各除以 K；长度不同则要按有效 token 数加权，不能机械平均。

**激活检查点**则只保存部分中间结果，反向时重新计算缺失的激活。它用计算换显存，不改变有效 batch 的定义。简单链式网络每隔 k 层保存一次，存储可粗略分成 (L/k) 个检查点与 k 层临时激活，取 k 接近 √L 可平衡二者；真实 Transformer 的最优方案还受算子大小影响。

两种手段能组合，但都不会自动减少优化器状态的容量。

## 深入算例与补充理解

### 从矩阵求导到训练循环

设 X 为 `[B,d]`、W 为 `[d,f]`、Y=XW，损失关于 Y 的梯度为 G。链式法则给出 `dX=G@W.T`、`dW=X.T@G`。可以逐元素验证第二个式子：某个 W[i,j] 对所有样本的输出 Y[b,j] 都有贡献，所以必须把 B 个样本的贡献加起来。

当一个参数在多处被共享，梯度也要把各条路径的贡献相加。这解释了为什么自动微分默认会累积 `.grad`，以及每步更新后为什么需要清理梯度。忘记清零不是“相当于更大的 batch”，因为中间参数已经更新，累积的是不同参数点的梯度。

### 16GB 静态状态并不意味着 16GB 卡可以训练

设 1B 参数用 16 字节账本，静态数组约为 16GB，转换为 GiB 约 14.9。若设备标称显存也是 16GB，仍可能很快 OOM，因为前向需要保存激活，反向和优化器也会创建临时数组。

又如一层显式保存 `[B,h,T,T]` Attention probabilities，B=4、h=16、T=4096、每元素两字节，单这一项就占 2 GiB。增加层数后更夸张。使用节省 Attention 中间状态的方法，改变的是这部分账本，不是模型参数本身。

### 怎样把 FLOPs 换成时间

假设模型训练需要 6×10²⁰ FLOPs，有 8 张卡，每卡对应精度的稠密峰值为 10¹⁵ FLOP/s，预期有效利用率为 0.5，则粗略时间为：

$$
t\approx\frac{6\times10^{20}}{8\times10^{15}\times0.5}=150000\text{ 秒}\approx41.7\text{ 小时}.
$$

这不是算力报价，也不是实际训练承诺。检查点写盘、数据准备、故障与调试都会增加实际完成时间。这个算例的价值是：先看数量级是否合理，再决定是否有必要搭实验。

### 为什么“只差一个转置”也可能很贵

若转置仅改变 view 的 stride，创建它本身可以很便宜；但下一个算子可能只对某种连续布局有高效实现，于是发生复制，或者采用更差的访存方式。做资源分析要覆盖整条数据流，不应只计 `transpose` 这一行的 CPU 时间。

小练习：对一个二维张量分别执行转置、变连续、矩阵乘法，记录形状、stride 和数据指针是否改变。目的不是记住某个版本的输出，而是建立“逻辑形状”和“物理布局”的区分。

## 8. 动手核算与自测

1. 手算一个 `[4096,1024] @ [1024,4096]` 的前向 FLOPs。
2. 对一个 1B 参数模型，分别列出 BF16 权重、BF16 梯度和两个 FP32 Adam 状态；然后再加主权重。比较两种账本。
3. 为什么把 ReLU 换成计算更复杂的 GELU，独立算子的耗时未必按 FLOPs 比例增加？
4. 梯度累积是否与大 batch 完全等价？考虑随机层、归约顺序和 batch 相关运算。

**参考思路：** 前向为 (2×4096×1024×4096)；权重和梯度各约 2GB，Adam 状态合计约 8GB，主权重再加约 4GB，均为十进制容量且未计激活；低强度算子主要受数据移动限制。
