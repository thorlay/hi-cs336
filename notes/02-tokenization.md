# 02｜Tokenization 与 BPE

## 为什么不直接用字符

模型处理有限词表里的整数 ID。字符粒度容易产生长序列；完整词粒度容易遇到未登录词和很大的词表。子词分词在词表大小与序列长度之间取折中。byte-level 方案从字节出发，可以表示任意 UTF-8 文本，但不保证一个 token 对应一个完整字符。

注意：字符串长度、UTF-8 字节数与 token 数是三个不同的量。

## 手算 BPE

为了只观察合并机制，假设已经完成预分词，得到三个字节片段：`aa`、`aa`、`ab`。相邻对 `(a,a)` 出现两次，`(a,b)` 出现一次。第一轮学习 `(a,a) → aa`，替换后得到 `[aa]`、`[aa]`、`[a,b]`。下一轮重新统计剩余相邻对。

训练学习合并的顺序；编码应用已学到的合并优先级。不能每次编码时根据新文本频率重新训练。并列频率的处理也应固定，才能得到可复现的词表。

真实实现还涉及预分词边界、特殊 token 与高效计数。上面的玩具例子没有覆盖这些接口要求。

## 正确性比速度先行

- 检查空串、ASCII、中文、emoji 与多字节字符。
- 对普通合法文本验证 `decode(encode(text)) == text`。
- 特殊 token 的允许/拒绝规则要与接口一致。
- 分块或并行统计时，边界不能截断预分词片段或特殊 token。

## 和训练成本的关系

相同文本在不同 tokenizer 下的 token 数可能不同。较短序列可能减少训练计算，但更大的词表也会扩大 embedding 和输出层。比较语言模型损失时，token 定义不同会影响每 token 的损失，不能直接用 perplexity 排名。
