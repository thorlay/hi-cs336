# 01｜语言模型训练全景

> 状态：入门速读笔记；详细解释见[对应逐讲教材](../textbook/01-overview-tokenization.md)。

## 从一个预测任务开始

给定一段 token 序列，因果语言模型预测下一个 token。若输入为 `[a, b, c]`，训练目标通常是 `[b, c, d]`：三个位置各产生一个词表上的概率分布。一次前向计算可以同时计算多个位置的损失，但位置 t 的表示不能读取未来 token。

设 logits 的形状为 `[B, T, V]`，分别表示 batch、序列长度和词表大小。对真实 token 的概率取负对数，再按有效位置求平均，就是常见的 token 级交叉熵。padding 位置通常需要排除，具体取决于数据组织。

## 四个相互制约的部分

- 数据决定模型能看到哪些模式，也决定重复、噪声和泄漏的风险。
- 模型把 token IDs 映射为 logits；结构决定参数量和计算模式。
- 优化器用梯度更新参数；学习率与数值精度影响稳定性。
- 评估检查模型能否在未见数据上工作，帮助识别训练之外的问题。

训练损失下降只说明当前训练目标被更好地拟合。它不能单独证明知识准确、推理可靠或没有数据泄漏。

## 一次训练步做什么

取 batch → 前向计算 → 损失 → 反向传播 → 裁剪梯度（若启用）→ 更新参数 → 清理梯度。

梯度累积时，多次前向/反向后才进行一次参数更新；损失缩放必须匹配预期的平均方式。比较实验时，要区分 microbatch、有效 batch、训练步数与实际处理的 token 数。

## 系统视角

总耗时来自计算、内存搬运、通信、数据准备与同步。提高矩阵乘法速度不一定提高端到端吞吐；例如数据加载停顿可能让 GPU 一直等待。先测量，再选择优化对象。

## 自测与实践

1. 为什么因果掩码允许并行训练，却仍然需要逐步自回归生成？
2. 梯度累积后，怎样保持与大 batch 的平均损失一致？
3. 固定同一小批数据反复训练，损失降不下去时，优先检查标签错位、掩码、梯度和参数更新。
